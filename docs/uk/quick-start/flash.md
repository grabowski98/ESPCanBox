# Прошивка

> [!NOTE]
> **Машинний переклад, потребує перевірки**
>
> Цю сторінку перекладено автоматично. Обов'язковим є англійський текст. Як надіслати
> виправлення: [Переклади](../../en/contributing/translations.md#send-your-work).

Ця сторінка веде від чистого комп'ютера до плати, на якій працює прошивка і відкривається її
веб-панель. Кроки 1-3 можна виконати без плати.

> [!NOTE]
> **Стан цього дерева прошивки**
>
> Ця прошивка збирається і проходить тести на ПК (усі середовища збираються, тести на
> комп'ютері збігаються з еталонами). Версію 2.0.0 перевірено на платі ESP32-S3-WROOM-1-N16R8 за
> [протоколом стендового тесту](../../en/testing/bench-test-protocol.md) і випробувано в одному
> автомобілі 20.11.2026.

**Де вводити команди.** У Windows вводьте всі команди цієї сторінки в **PowerShell** (або у
Windows Terminal). Git Bash для прошивки не потрібен, лише для тестів на комп'ютері та для сторінок
розділу [Під свій автомобіль](../make-it-yours/porting-checklist.md). У Linux і
macOS користуйтеся звичайним терміналом.

## Найшвидше: готовий образ у браузері {#ready-image-in-the-browser}

Це рекомендований спосіб для першого встановлення. Не потрібні ні PlatformIO, ні пакет Python
для прошивки, ні зазвичай додатковий драйвер: лише Chrome або Edge і файл образу. Спосіб працює і
там, де `pip install esptool` не вдається (на дуже новій версії Python встановлення може
зупинитися помилкою збирання однієї із залежностей).

1. Завантажте образ. Готові образи є на сторінці проєкту в розділі **Releases**, по парі на
   кожне середовище без передавання в CAN (`listen`, `decoder`, `listen_wifi`, `decoder_wifi`,
   `listen_generic_wifi`; прочитайте [Яке середовище](#which-environment)). Образу з передаванням
   у готовому вигляді немає ніколи. Виберіть файл за завданням:

    | Файл | Адреса | Для чого |
    |---|---|---|
    | `<environment>-<version>-merged.bin` | `0x0` | перше встановлення; стирає всю flash-пам'ять разом зі збереженими налаштуваннями (потім пристрій створить новий пароль Wi-Fi) |
    | `<environment>-<version>.bin` | `0x10000` | оновлення пристрою, на якому вже працює ця прошивка; збережені налаштування лишаються |

    Власна збірка (кроки 1-3 нижче) дає образ застосунку
    `.pio/build/<environment>/firmware.bin`: як і файл без `-merged`, він записується за адресою
    `0x10000` і лише оновлює пристрій, на якому вже працює ця прошивка.

2. Підключіть плату до комп'ютера USB-кабелем для даних, у власне гніздо USB мікросхеми
   ESP32-S3 (див. [Підключіть плату](#4-connect-the-board)).
3. Відкрийте <https://espressif.github.io/esptool-js/> у Chrome або Edge.
4. Натисніть **Connect** і виберіть порт плати у списку, який покаже браузер.
5. Введіть адресу з таблиці в поле адреси, поруч виберіть файл образу й натисніть **Program**.
   Кнопки на модулі не потрібні: плата перезавантажується сама.
6. Очікувано: журнал на сторінці закінчується рядком `Hash of data verified.` Якщо нова програма
   не запустилася, натисніть RESET або перепідключіть кабель.

Консоль на тій сторінці лише показує, що виводить пристрій; вводити команди в ній не можна. Щоб
вводити команди, один раз встановіть невеликий послідовний термінал Python і запустіть його (у
Linux і macOS вводьте `python3` замість `python`):

```text
python -m pip install pyserial
python -m serial.tools.miniterm - 115200
```

`-` змушує його показати список портів; виберіть плату. Введені символи не відображаються:
вводьте команду наосліп і завершуйте її Enter. Вихід із термінала: Ctrl+].

Після першого встановлення `ver` показує версію. Збірка з мережею потім відкриває свою мережу
Wi-Fi `<project name>-XXXX` з панеллю за адресою `http://10.50.8.1`, щонайбільше для чотирьох
пристроїв одночасно. Далі перейдіть до [Перший запуск](first-boot.md#2-read-the-password-from-the-usb-console),
щоб прочитати пароль.

<details class="note" markdown="1">
<summary>Інший шлях: esptool у командному рядку</summary>

Якщо `esptool` встановлюється на вашому комп'ютері, він записує ті самі файли за тими самими
адресами. Використайте одну з двох команд запису:

```text
python -m pip install esptool
python -m esptool --chip esp32s3 write-flash 0x0 <environment>-<version>-merged.bin
python -m esptool --chip esp32s3 write-flash 0x10000 <environment>-<version>.bin
```

</details>

**Зібрати самому.** Пронумеровані кроки нижче збирають прошивку з вихідного коду в PlatformIO і
завантажують її через USB. Використовуйте їх, якщо для вашого завдання немає готового образу або
якщо ви змінюєте код.

## 1. Встановіть uv {#1-install-uv}

Прошивку збирають за допомогою [PlatformIO](https://platformio.org/). Встановлювати його самому
не треба: `uvx platformio ...` завантажує і запускає його через [uv](https://docs.astral.sh/uv/) —
невеликий інструмент для запуску програм.

### Windows {#windows}

1. Відкрийте PowerShell і виконайте:

    ```powershell
    winget install --id=astral-sh.uv -e
    ```

2. Закрийте PowerShell і відкрийте його знову, щоб він знайшов `uv`.

Для прошивки не потрібно; потрібно для тестів на комп'ютері та для розділу «Під свій автомобіль»:
[Git for Windows](https://git-scm.com/download/win). До нього входить **Git Bash**, який запускає
тестові скрипти й команди цих сторінок.

### Linux {#linux}

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Щоб користуватися портом USB без root, додайте себе до групи послідовних портів (`dialout`
у Debian і Ubuntu, `uucp` в Arch) і встановіть правила udev для PlatformIO, як описано
в [документації PlatformIO](https://docs.platformio.org/en/latest/core/installation/udev-rules.html).
Вийдіть із системи і увійдіть знову.

### macOS {#macos}

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

або, з Homebrew, `brew install uv`.

### Перевірте {#check-it}

Відкрийте новий термінал і виконайте:

```text
uvx platformio --version
```

Очікуваний результат: один рядок із версією PlatformIO, наприклад
`PlatformIO Core, version 6.2.0`. Перший виклик завантажує PlatformIO і триває трохи часу;
наступні запускаються одразу. Якщо бачите «command not found» або «not recognized», закрийте
термінал, відкрийте новий і спробуйте ще раз.

Якщо вам зручніше працювати в редакторі, підійде і розширення PlatformIO для VS Code: відкрийте
теку `firmware` і виберіть середовище в рядку стану. Команди нижче — це те, що розширення
виконує за вас.

## 2. Отримайте код {#2-get-the-code}

1. Відкрийте сторінку проєкту (репозиторій, де ви знайшли цей посібник) і виберіть
   **Code → Download ZIP**. Якщо ви користуєтеся Git, підійде і `git clone`.
2. Розпакуйте ZIP. У Windows: правий клік на файлі → **Видобути все**.
3. Відкрийте розпаковану теку, у якій поруч видно `firmware`, `docs` і `README.md`. Після
   розпакування вона часто лежить на рівень глибше, у теці з тією самою назвою.
4. Відкрийте термінал у теці `firmware` усередині неї:
    - **Windows:** відкрийте `firmware` у Провіднику, клацніть адресний рядок, введіть
      `powershell` і натисніть Enter. (У Windows 11 підійде і правий клік на порожньому місці →
      **Відкрити в терміналі**.)
    - **Linux і macOS:** відкрийте термінал, введіть `cd ` (з пробілом), перетягніть теку
      `firmware` у вікно і натисніть Enter.

Усі команди нижче виконуються в цьому терміналі, у теці `firmware`.

## 3. Зберіть {#3-build}

```text
uvx platformio run -e listen_wifi
```

Ця програма лише слухає автомобіль і має веб-панель. Без панелі використайте тут і в кроці 5
`-e listen`.

Перша збірка завантажує платформу ESP32 (`espressif32@8.0.0`, закріплена в `platformio.ini`)
і компілятор. Завантаження велике і може тривати багато хвилин; не переривайте його. Наступні
збірки використовують його повторно.

Очікуваний результат: наприкінці PlatformIO виводить `SUCCESS`. Програма лежить у
`.pio/build/listen_wifi/firmware.bin`. Якщо замість цього бачите `Error`, прочитайте перший рядок
помилки: помилка мережі означає, що завантаження обірвалося; виконайте команду ще раз.

### Яке середовище {#which-environment}

**Середовище** — це іменований набір параметрів збірки у `firmware/platformio.ini`. Воно
визначає, що пристрою дозволено робити. На столі достатньо `listen_wifi`. Для іншого автомобіля,
не еталонного, згодом використайте `listen_generic_wifi`.

<details class="note" markdown="1">
<summary>Усі шість середовищ і збірка всіх одразу</summary>

Ніколи не змінюйте режим редагуванням `src/config.h`; натомість виберіть середовище.

| Середовище | Режим | Панель Wi-Fi та оновлення через Wi-Fi | Передає на шину автомобіля | Для чого |
|---|---|---|---|---|
| `listen` (типово) | паралельний режим (поруч з адаптером) | ні | ні (у програмі немає коду передачі) | перша прошивка, стенд, прослуховування поруч з CAN-адаптером |
| `decoder` | режим декодера | ні | ні | заміна CAN-адаптера, без мережі |
| `listen_wifi` | паралельний режим | так | ні | прослуховування з веб-панеллю |
| `decoder_wifi` | режим декодера | так | ні | заміна CAN-адаптера, з веб-панеллю |
| `decoder_tx_wifi` | режим декодера | так | **лише кадр `15B`, після `cantx on` і перезапуску** | зміни персоналізації з екрана магнітоли; спочатку прочитайте [Передача на шину CAN](../../en/safety/transmit.md) |
| `listen_generic_wifi` | паралельний режим | так | ні | інший автомобіль: профіль `generic`, магнітола `none`, записує шину і нічого не надсилає на магнітолу |

«Паралельний режим (поруч з адаптером)» — це режим лише прослуховування: пристрій працює
поруч з CAN-адаптером і нічого не надсилає. Консоль називає той самий режим
`alongside the box`.

Просто `uvx platformio run` (без `-e`) збирає `listen` — безпечний режим без мережі.

Щоб зібрати всі шість середовищ одразу, виконайте `make build` у кореневій теці (потрібен
`make`, якого немає в Git Bash; звичайні команди `uvx platformio run -e ...` працюють
завжди).

Необов'язкові налаштування, які залишаються на вашому комп'ютері, записуйте у
`firmware/platformio_override.ini` (скопіюйте `platformio_override.sample.ini`). У зразку
показано власну плату (`listen_mine`) і власний профіль автомобіля (`listen_mycar`). Пробний
кадр `1A9` існує, лише якщо ви там свідомо додасте `-DCAN_TX_EXPERIMENTAL=1` до
збірки з передачею.

</details>

> [!WARNING]
> **Режим декодера лише без CAN-адаптера**
>
> Прошивайте середовище `decoder*` лише тоді, коли сторонній CAN-адаптер від'єднаний, або на
> стенді. Два пристрої на лінії даних магнітоли і два джерела на проводі ACC замикають виходи
> один одного.

## 4. Підключіть плату {#4-connect-the-board}

1. Під'єднайте плату до комп'ютера кабелем USB, який передає дані (не кабелем лише для
   заряджання). На платах із двома гніздами USB використовуйте те, що підключене безпосередньо
   до ESP32-S3 (часто з написом `USB`, а не `UART`): ця прошивка працює через вбудований USB
   чипа.
2. Перегляньте список портів:

    ```text
    uvx platformio device list
    ```

Очікуваний результат: після під'єднання плати з'являється новий рядок. Windows 10 і 11 зазвичай
не потребують додаткового драйвера для цього порту.

| Система | Порт виглядає так |
|---|---|
| Windows | `COM5` (будь-який номер) |
| Linux | `/dev/ttyACM0` |
| macOS | `/dev/cu.usbmodem1101` (будь-який номер) |

Нічого нового у списку? Спробуйте інший кабель. Якщо порту все одно немає, запустіть
завантажувач вручну, див.
[Якщо завантаження не починається](#if-the-upload-does-not-start-bootloader-mode).

## 5. Завантажте прошивку {#5-upload}

```text
uvx platformio run -e listen_wifi -t upload
```

PlatformIO сам знаходить порт. Якщо підключено кілька плат, вкажіть його:
`uvx platformio run -e listen_wifi -t upload --upload-port COM5`.

Очікуваний результат: завантаження закінчується `[SUCCESS]`.

- «could not open port» або «Access is denied»: порт зайнятий. Закрийте монітор (Ctrl+C) в
  іншому вікні і запустіть завантаження ще раз.
- Порт не знайдено: спробуйте інший кабель, потім режим завантажувача нижче.

Завантаження через USB зберігає запам'ятовані налаштування (гучність, таблицю кнопок, пароль
Wi-Fi).

### Якщо завантаження не починається: режим завантажувача {#if-the-upload-does-not-start-bootloader-mode}

Зазвичай інструмент завантаження сам перезапускає ESP32-S3 у вбудований завантажувач через USB.
Якщо порт не з'являється або завантаження зупиняється з помилкою з'єднання (наприклад, після
програми, яка падає під час запуску), запустіть завантажувач вручну:

1. Утримуйте кнопку **BOOT** (на деяких платах позначена `0` або `IO0`).
2. Натисніть і відпустіть **RESET** (`RST` або `EN`) або під'єднайте кабель USB, утримуючи BOOT.
3. Відпустіть BOOT. Порт з'явиться знову; виконайте команду завантаження.
4. Після завантаження натисніть RESET один раз, щоб запустилася нова програма.

Це кнопки плати розробника ESP32-S3, а не несучої плати.

## 6. Стежте за консоллю {#6-watch-the-console}

```text
uvx platformio device monitor
```

Швидкість (115200) береться з `platformio.ini`. Натисніть RESET на платі, щоб побачити рядки
запуску. Вони виглядають так (перший рядок починається з назви проєкту; `listen` виводить
`network=no`, `listen_wifi` — `network=yes`):

```text
# <project name>. CAN 125 kbit/s LISTEN ONLY. Mode: alongside the box (sends nothing).
# profile: car=psa_aee2010 radio=xp
# version: <product> 2.0.0, built <date and time>, network=yes, volume=40%
# can=ok audio=ok radio=ok
# start: <reset reason>
```

RESET також на мить від'єднує порт USB. Якщо монітор зупинився або ви пропустили рядки запуску,
запустіть монітор знову і введіть `ver`.

> [!NOTE]
> **Введених символів не видно**
>
> Літери, які ви вводите, не з'являються на екрані. Це нормально: прошивка не повертає їх
> назад. Введіть команду наосліп і натисніть Enter; відповідь з'явиться в новому рядку.

Введіть `help` і Enter, щоб побачити список команд, `ver` — версію, `stat` — стан. Щоб вийти
з монітора, натисніть Ctrl+C.

`FAIL` у рядку `can=... audio=... radio=...` означає, що якийсь драйвер не запустився. Тоді
пристрій залишається в безпечному стані (виходи 12 V вимкнені, нічого не надсилається),
а світлодіод на платі світиться червоним. Він не перезапускається по колу.

## Стирання всього {#erasing-everything}

`uvx platformio run -e listen -t erase` стирає всю flash-пам'ять, разом із запам'ятованими
налаштуваннями. Під час наступного запуску мережі буде створено новий пароль Wi-Fi. Після цього
завантажте програму знову.
