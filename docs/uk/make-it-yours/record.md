# Запишіть шину

> [!NOTE]
> **Машинний переклад, потребує перевірки**
>
> Цю сторінку перекладено автоматично. Обов'язковим є англійський текст. Як надіслати
> виправлення: [Переклади](../../en/contributing/translations.md#send-your-work).

Запис (capture) — це текстовий файл з кожним кадром CAN, який бачив пристрій, по порядку і з
часом. Ви записуєте його, поки щось робите в автомобілі: натискаєте кнопку, відчиняєте двері,
вмикаєте задню передачу. Потім ви шукаєте біти, що змінилися в ці моменти ([Декодування](decode.md)).

Спершу вам потрібні факти зі сторінки [Знайдіть свою шину](find-your-bus.md): дроти, тип шини і
швидкість передачі.

> [!CAUTION]
> **Для запису використовуйте збірку лише прослуховування**
>
> Використовуйте `listen_generic_wifi` або окремий сніфер у `extras/sniffer/`. Обидва лише
> слухають. Не записуйте невідомий автомобіль збіркою, яка може передавати.

## Формат {#the-format}

Одна подія на рядок, той самий формат усюди в цьому проєкті:

```
(416.094276) can0 532#0800000000000000      CAN frame: time in s, interface, ID#DATA
(12.346900) uartA FD04021117                UART bytes (only the sniffer's recorder variant)
# STEP 3 19:06:41.149 Volume + three times   comment line: a marker
# stat rx=30529 ...                          comment line: statistics
```

Рядки, що починаються з `#`, — коментарі. Деякі коментарі є **маркерами**: рядками, які ви додаєте
під час запису, у момент, коли починаєте дію. Саме маркери роблять запис легким для декодування.
Кожен інструмент пише маркери свого виду:

| Інструмент | Рядок маркера |
|---|---|
| `record.py` | `# MARKER n (time) computer clock HH:MM:SS: text` |
| `record_serial.py` (сніфер) | `# STEP n HH:MM:SS.mmm text` (Enter), `# MARK d HH:MM:SS.mmm` (цифра `1`–`9` + Enter) |

Більше про формат: [Записи з автомобіля](../../en/testing/captures.md).

## Виберіть інструмент {#choose-a-tool}

- Використовуйте `firmware/tools/record.py`, якщо маєте пристрій з `listen_generic_wifi` і ноутбук
  у його мережі Wi-Fi. Файл потрапляє в теку `logs` поруч із текою репозиторію.
- Використовуйте `extras/sniffer/record_serial.py`, якщо маєте окрему плату сніфера через USB.
  Файл потрапляє в теку, задану через `--out`.
- Використовуйте `dump` у консолі USB лише для швидкого погляду: він не пише маркерів.

## Спершу сплануйте кроки {#plan-the-steps-first}

Запишіть кроки, перш ніж сісти в автомобіль. Добрий план:

- **Почніть із кількох секунд без дій**, щоб запис показав автомобіль у спокої.
- **Одна дія на крок.** «Гучніше» і «тихіше» — це два кроки.
- **Повторіть кожну дію тричі**, з паузою 2–3 секунди. Біт, що змінюється тричі, — ваш сигнал.
  Біт, що змінюється весь час, — це лічильник або шум.
- **Ставте маркер безпосередньо перед дією**, а не після неї.
- **Записуйте стан автомобіля** на початку кожного кроку: запалювання, двигун, двері, що показує
  магнітола.

Приклад плану англійською — `extras/sniffer/scenarios/example_buttons.txt`. Він починається так:

```
START: ignition off, key out, radio off, wait 10 s
Insert the key, ignition on (engine off), wait until the radio has started, then 10 s
Steering wheel: volume + three times, every 2 s
Steering wheel: volume - three times, every 2 s
```

Записи еталонного автомобіля у `firmware/test_data/captures/` зроблено за такими планами. Їхні
рядки кроків польською (`# KROK n` = «крок n») і збережені так, як були записані.

## Запис через Wi-Fi за допомогою `record.py` {#record-over-wi-fi-with-recordpy}

1. Зберіть і прошийте `listen_generic_wifi` зі знайденою швидкістю передачі: з теки `firmware`,
   `uvx platformio run -e listen_generic_wifi -t upload` ([Прошивка](../quick-start/flash.md)).
2. Підключіть пристрій до автомобіля ([Підключення CAN](../../en/install-in-car/can-connection.md)).
3. Підключіть ноутбук до мережі Wi-Fi пристрою ([Перший запуск](../quick-start/first-boot.md)).
   Використовуйте ноутбук на батареї або з живленням від автомобіля.
4. З теки репозиторію запустіть:

    ```
    python -I firmware/tools/record.py
    ```

    Типова адреса — `10.50.8.1`. Іншу адресу передайте першим аргументом.
5. Коли буде запит, введіть пароль пристрою. Це той самий ключ, що й у мережі Wi-Fi; його показує
   `wifi showpass` у консолі USB ([Перший запуск](../quick-start/first-boot.md)). Він не
   показується на екрані й не зберігається.
6. Дочекайтеся `[ok] connected, recording`. Скрипт виводить назви двох файлів: один з кадрами CAN,
   другий з рядками консолі пристрою.
7. Для кожного кроку: введіть короткий текст (наприклад `volume up 3x`), натисніть Enter, потім
   виконайте дію.
8. Щоб зупинити, введіть `q` і Enter.

`record.py` лише читає з пристрою. Він не надсилає команд і нічого не змінює. Кадри `336`, `3B6` і
`2B6` записуються як `# masked`, бо на еталонному автомобілі вони містять VIN. У вашому автомобілі
VIN може бути в інших кадрах: знайдіть їх, перш ніж будь-чим ділитися
([Поділіться своїм автомобілем](contribute.md)).

> [!WARNING]
> **`record.py` завжди приховує `336`, `3B6` і `2B6`**
>
> В іншому автомобілі ці три ID можуть нести звичайні сигнали, а скрипт не має параметра, щоб
> їх залишити. Якщо не можете знайти сигнал, зробіть один запис сніфером або через `dump`:
> обидва зберігають усі кадри, тож очистьте такий файл, перш ніж ним ділитися.

Якщо зв'язок Wi-Fi обривається, скрипт продовжує спроби. Кадри, які пристрій не зміг передати,
записуються як `# lost N frames`. Пристрій тримає в пам'яті близько 9 s кадрів, тож під час коротких
обривів нічого не втрачається.

> [!NOTE]
> **Не записуйте через веб-панель у браузері**
>
> Перегляд CAN у веб-панелі записує лише тоді, коли його вкладка браузера видима. Коли автор під
> час запису в панелі перейшов на іншу вкладку, було втрачено 26 593 кадри (виміряно (measured):
> рядок `# zgubiono 26593 ramek`, польською «втрачено 26593 кадри», у
> `centralka_can_20261117_184411.log`). Використовуйте `record.py`.

## Запис через USB сніфером {#record-over-usb-with-the-sniffer}

Сніфер — це невелика окрема програма для плати ESP32-S3 з модулем трансивера CAN і взагалі без
дроту передачі. Збирання, підключення і команда запису описані в `extras/sniffer/README.md`.
Коротко:

```
uv run --with pyserial python -I extras/sniffer/record_serial.py COM7 --scenario extras/sniffer/scenarios/example_buttons.txt
```

Запускайте його з теки репозиторію. Замість `COM7` вкажіть свій порт: його показує
`uvx platformio device list`. Скрипт показує наступний крок сценарію. Натисніть Enter, коли
починаєте його.

## Як маркери отримують час {#how-markers-get-their-time}

Рядок коментаря не має власного часу. Інструмент декодування ([Декодування](decode.md)) дає кожному
маркеру час першого кадру CAN після нього. Маркер від `record.py` несе в дужках час пристрою, і
тоді використовується саме він.

Це важливо, коли шина спить. В еталонному записі `can_20261110_190421.log` шина мовчала під час
перших двох кроків («старт, чекати 10 s» та «запалювання ввімкнено»). Обидва маркери отримали однаковий час —
момент, коли шина прокинулася:

```
    1  line     21     397.922 s  # KROK 1 19:04:37.265 START: zaplon OFF, kluczyk wyjety, drzwi zamkniete, czekaj 10 s (magistrala w spoczynku)
    2  line     39     397.922 s  # KROK 2 19:04:54.247 Wloz kluczyk i wlacz zaplon (bez odpalania), czekaj 10 s
```

Тож для «запалювання ввімкнено» дивіться на перші кадри запису, а не на зміну біля маркера.

## Після запису {#after-the-recording}

- Перевірте числа, які скрипт виводить наприкінці: кадри, маркери, втрачені кадри.
- Відкрийте файл у текстовому редакторі й прочитайте рядки коментарів. Тексти ваших маркерів
  копіюються у файл без змін: не вписуйте в них нічого приватного.
- Зберігайте оригінальний файл. Працюйте з копією.
- Перш ніж ділитися записом з кимось, видаліть VIN і перевірте файл
  ([Поділіться своїм автомобілем](contribute.md)).

Далі: [Декодуйте кадри](decode.md).
