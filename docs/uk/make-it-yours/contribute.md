# Поділіться своїм автомобілем

> [!NOTE]
> **Машинний переклад, потребує перевірки**
>
> Цю сторінку перекладено автоматично. Обов'язковим є англійський текст. Як надіслати
> виправлення: [Переклади](../../en/contributing/translations.md#send-your-work).

Ви виміряли автомобіль, якого немає у `vehicles/SUPPORTED.md`. Ваші нотатки допоможуть наступній
людині з таким самим автомобілем, навіть без профілю у прошивці. Ця сторінка пояснює, чим
поділитися, як спершу це очистити і куди йде кожен файл. Загальні правила для внесків лежать у
`CONTRIBUTING.md` у корені репозиторію.

Це хобі-проєкт з одним супровідником. Ніхто не обіцяє відповіді чи перевірки в якийсь строк.

## Чим можна поділитися {#what-you-can-share}

| Внесок | Куди він іде |
|---|---|
| Опис автомобіля та його шини | `vehicles/<make>-<model>-<year>/README.md`, на основі `vehicles/_template/README.md` |
| Кадри й сигнали | `vehicles/<make>-<model>-<year>/<car>.dbc`, кожен коментар починається зі статусу |
| Вигляд роз'ємів і таблиці контактів | `vehicles/<make>-<model>-<year>/wiring.md`, із зазначенням, з якого боку ви дивилися |
| Записи, які використовує тест | `firmware/test_data/captures/`, з одним рядком у його `README.md` |
| Профіль прошивки | `firmware/lib/car_<name>/` ([Напишіть профіль автомобіля](write-a-profile.md)) |
| Його тест на комп'ютері | `firmware/test_host/<name>_car.cpp`, еталон у `firmware/test_host/expected/`, один блок у `firmware/tools/run_host_tests.sh` ([Перевірте свій профіль](test-your-profile.md)) |
| Що ваша магнітола робить з кожним кодом кнопки | сторінка вашого автомобіля, розділ «Radio side» ([Зіставте кнопки з магнітолою](radio-mapping.md)) |
| Рядок для списку підтримуваних | `vehicles/SUPPORTED.md`: автомобіль, профіль, статус, що працює, посилання на вашу сторінку |

Pull request лише зі сторінкою автомобіля вітається. Так само вітається issue з шаблоном
«New vehicle», якщо ви не користуєтеся Git.

## Правила для фактів {#the-rules-for-facts}

- Кожен факт має статус: **виміряно** (measured; як саме: мультиметр, запис, консоль пристрою; для
  запису: файл і крок) або **не перевірено** (unverified; джерело: публічна база даних, форум,
  креслення продавця).
- Висновок не є вимірюванням. «Напруги схожі на low-speed fault-tolerant CAN» — це висновок;
  напишіть, що його підтвердить.
- Пишіть лише те, що бачили. «Не виміряно» — це добрий запис.
- Лише ваша власна робота: ваші записи, фото й слова. Не надсилайте декомпільований код, прошивки
  чи застосунки виробників адаптерів або магнітол, таблиці, взяті з них, даташити або код,
  скопійований з проєктів з несумісною ліцензією. Замість копіювання дайте посилання на публічне
  джерело.

## Спершу очистіть свої записи {#clean-your-recordings-first}

Запис шини може містити VIN вашого автомобіля, а також показує, коли і як ви їздили. Очистіть
кожен файл, перш ніж він покине ваш комп'ютер.

### 1. Знайдіть кадри, що містять VIN {#1-find-the-frames-that-carry-the-vin}

На еталонному автомобілі VIN міститься в кадрах `336`, `3B6` і `2B6` (виміряно: записи еталонного
автомобіля). Ці три ідентифікатори є типовими для інструмента очищення і для `record.py`. **В
автомобілі іншої марки VIN може бути в інших кадрах або взагалі не на цій шині.** З'ясуйте це,
перш ніж ділитися:

1. Візьміть VIN зі свідоцтва про реєстрацію. Не вписуйте його в жоден файл, яким будете ділитися.
2. VIN — це 17 літер і цифр. Перетворіть перші три символи на шістнадцяткові коди ASCII:
   наприклад `V` = `56`, `F` = `46`, `3` = `33`.
3. Знайдіть ці байти у своєму записі в текстовому редакторі, а потім шістнадцяткові коди інших
   символів. Будь-який кадр, дані якого складаються в частину VIN, — це кадр VIN. Записані текстом, 17
   символів не вміщуються в один 8-байтовий кадр, тож очікуйте більше одного. Якщо нічого не
   збігається, автомобіль, можливо, не надсилає VIN текстом на цій шині; напишіть про це на
   сторінці свого автомобіля.
4. Запишіть ідентифікатори. Якщо не знайшли жодного, напишіть на сторінці автомобіля «VIN frames:
   none found».

### 2. Перезапишіть їх {#2-overwrite-them}

З кореня репозиторію:

```bash
python -I tools/sanitize_capture.py my_drive.log my_drive_clean.log --ids 336,3B6,2B6,ABC
python -I tools/sanitize_capture.py --check my_drive_clean.log --ids 336,3B6,2B6,ABC
```

Замініть `ABC` на ідентифікатори своїх кадрів VIN (три типові залиште, вони не шкодять).
Інструмент перезаписує дані цих кадрів нулями тієї самої довжини: кількість рядків, час,
ідентифікатори й довжини лишаються як були, тож тести й надалі працюють. Він також замінює рядок
заголовка, де згадано ваш послідовний порт, на `# capture`. `--check` має показати `0 problem(s)`.

### 3. Самі прочитайте коментарі {#3-read-the-comments-yourself}

Інструмент копіює рядки коментарів (`# ...`) без змін. У них ваші тексти маркерів. Відкрийте файл
і пошукайте імена, місця, адреси, назви мереж чи будь-що інше приватне.

### 4. Перевірте все, що додаєте {#4-scan-everything-you-add}

```bash
python -I tools/scan_private.py .
```

Скрипт шукає VIN, кадри VIN з даними, адреси електронної пошти, шляхи користувачів Windows,
MAC-адреси і назви мереж пристрою зі справжнім суфіксом. Він має завершитися без помилок.

> [!WARNING]
> **Сканер знає лише формат VIN еталонного автомобіля**
>
> `scan_private.py` розпізнає VIN групи PSA (`VF3` + 14 символів) і кадри VIN PSA. Він не знає
> VIN іншої марки чи ваших власних кадрів VIN. Кроки 1–3 однаково лишаються вашою роботою.

## Перш ніж відкрити pull request {#before-you-open-a-pull-request}

У шаблоні pull request є список перевірок. Для нового автомобіля важливі ось ці:

| Перевірка | Команда | Очікується |
|---|---|---|
| Записи очищено | `python -I tools/sanitize_capture.py --check <files> --ids ...` | `0 problem(s)` |
| Немає приватних даних | `python -I tools/scan_private.py .` | без помилок |
| Тести на комп'ютері (з `firmware/`) | `bash tools/run_host_tests.sh` | `All tests match the references.` |
| Шари (з `firmware/`) | `python -I tools/check_layering.py` | `Layering OK.` |
| Ваша збірка (з `firmware/`) | `uvx platformio run -e listen_mycar` | `SUCCESS` |
| Посилання документації, якщо ви змінювали `docs/` | `python -I tools/check_doc_links.py` | немає мертвих посилань |

Ваш `platformio_override.ini` лишається на вашому комп'ютері: Git його не відстежує. Напишіть у
pull request, яке середовище збірки ви використали для свого автомобіля і чи пробували прошивку на
платі та в автомобілі.

Не змінюйте наявні еталони тестів (`firmware/test_host/expected/`, `golden/`, `golden_060/`) у pull
request, що додає автомобіль. Додати власний файл еталона можна.

## Передача не входить у внесок автомобіля {#transmission-is-not-part-of-a-car-contribution}

Профіль, зібраний з `-DCAR_PROFILE=CUSTOM`, не може передавати, і прошивка не дає змоги додати
кадр для передачі під час роботи. Кадр, який пристрій може надсилати, потребує власного
вимірювання, перевірки вмісту, написаної на C++, тесту на комп'ютері та іменованого профілю у
`firmware/src/config.h`. Це окреме обговорення, а не частина додавання автомобіля: прочитайте
[Передача на шину CAN](../../en/safety/transmit.md) і спершу відкрийте issue.
