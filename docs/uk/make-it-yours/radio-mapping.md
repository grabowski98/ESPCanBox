# Зіставте кнопки з магнітолою

> [!NOTE]
> **Машинний переклад, потребує перевірки**
>
> Цю сторінку перекладено автоматично. Обов'язковим є англійський текст. Як надіслати
> виправлення: [Переклади](../../en/contributing/translations.md#send-your-work).

Профіль автомобіля визначає, **які біти CAN відповідають якій кнопці**. Протокол магнітоли визначає,
**який код магнітола отримує для цієї кнопки**. Між ними стоїть список логічних назв кнопок,
`KeyId`. Ця сторінка пояснює ці три частини і як змінити, що робить кнопка в магнітолі, з
перезбиранням прошивки або без нього.

## Три таблиці {#three-tables}

```text
CAN frame ──► car profile ──► logical button ──► radio protocol ──► key code ──► remapping ──► radio
              keys / knobs      KeyId             keyCode()          e.g. 14       map FROM TO
```

| Частина | Файл | Залежить від |
|---|---|---|
| біти CAN -> `KeyId` | ваш профіль, таблиці `keys` і `knobs` ([Напишіть профіль автомобіля](write-a-profile.md)) | автомобіля |
| `KeyId` -> код кнопки | протокол магнітоли, `firmware/lib/radio_xp/protocol_xp.cpp` (`xp::keyCode`) | протоколу магнітоли |
| код кнопки -> інший код кнопки | таблиця перепризначень, під час роботи, зберігається в налаштуваннях пристрою | вашого смаку |

Профіль автомобіля не знає кодів магнітоли, а протокол магнітоли не знає ідентифікаторів CAN.
Це перевіряє `tools/check_layering.py`.

## Доступні протоколи магнітоли {#radio-protocols-available}

| Прапорець збірки | Протокол | Що він робить |
|---|---|---|
| `-DRADIO_PROTOCOL=XP` (типово) | `xp` | протокол CAN-адаптера Simple Soft («XP») до магнітоли Android на платформі FYT, UART 38400 8N1. Використовуються лише команди, побачені на лінії: [Протокол XP](../../en/reference/xp-protocol.md) |
| `-DRADIO_PROTOCOL=NONE` | `none` | без магнітоли: UART не запускається, жодна кнопка не має коду, нічого ніколи не надсилається |
| `-DRADIO_PROTOCOL=CUSTOM` | ваш | ваш власний протокол у `firmware/lib/radio_<назва>`, задається через `RADIO_PROTOCOL_CUSTOM_HEADER` і `RADIO_PROTOCOL_CUSTOM_OBJECT` (шаблон: `firmware/lib/radio_example`). На CAN лише прослуховування: збірка з передаванням зупиняється з помилкою |

`listen_generic_wifi` використовує `none`. Ваш власний профіль із середовищем `listen_mycar`
використовує `xp`, але в паралельному режимі (поруч з адаптером) магнітолі все одно нічого не
надсилається.

> [!NOTE]
> **Іншого протоколу магнітоли поки немає**
>
> Дані автомобіля для екрана магнітоли (двері, бортовий комп'ютер, клімат-контроль,
> налаштування ...) потрапляють до протоколу магнітоли через кодувальники в `RadioProtocol`
> (`firmware/lib/core/radio_protocol.h`), як нейтральні типи. Решта логіки XP (зв'язок
> з магнітолою, кадри парктроніків і кнопок, команди від магнітоли) досі вбудована в декодер.
> Кожен кадр до магнітоли, зокрема від кодувальників, отримує обрамлення XP (заголовок `2E`,
> довжина, контрольна сума XP), і кадри XP живлення (`EA`), парктроніків (`32`), перешкоди (`3E`)
> та кнопок (`20`) теж надсилаються: функції обрамлення в `RadioProtocol` поки немає. Тож
> новому протоколу магнітоли потрібні також зміни у `firmware/src/config.h` і `firmware/lib/app/`.
> Це є в планах. Новий протокол треба писати на основі власних вимірювань лінії до магнітоли, а не
> з декомпільованих застосунків чи прошивок адаптерів.

## Логічні кнопки та коди XP {#logical-buttons-and-xp-codes}

Назви описують кнопку еталонного автомобіля (Peugeot 508 SW 2015). Для свого автомобіля
використовуйте назву з найближчим значенням. Код XP — це те, що магнітола отримує в кадрі кнопки
`20` (DATA[0] = код, DATA[1] = 1 натиснуто, 2 утримується, 0 відпущено). Це кадр UART: його байти
даних рахують від DATA[0], як на сторінці [Протокол магнітоли XP](../../en/reference/xp-protocol.md).
Байти CAN на інших сторінках рахують від байта 1.

| `KeyId` | Кнопка на еталонному автомобілі | Код XP |
|---|---|---|
| `VOLUME_UP` | гучність + на кермі | `14` |
| `VOLUME_DOWN` | гучність - на кермі | `15` |
| `MUTE` | обидві кнопки гучності разом | `16` |
| `PHONE` | кнопка телефону на кермі | `30` |
| `LIST` | LIST на кермі | `50` |
| `WHEEL_KNOB_PRESS` | натискання коліщатка на кермі | `07` |
| `SOURCE` | SRC | `21` |
| `TRIP` | кнопка бортового комп'ютера на підрульовому перемикачі склоочисників | `23` |
| `NAV` | панель: NAV | `9E` |
| `MEDIA` | панель: MEDIA | `A0` |
| `SCROLL_LEFT` | панель: пошук ліворуч | `97` |
| `ZOOM_IN` | панель: масштаб + | `9C` |
| `SCROLL_RIGHT` | панель: пошук праворуч | `98` |
| `TEL` | панель: TEL | `9F` |
| `SETUP` | панель: SETUP | `99` |
| `DRIVE` | панель: DRIVE | `9B` |
| `MOON` | панель: вимкнення екрана (місяць) | `A4` |
| `ZOOM_OUT` | панель: масштаб - | `9D` |
| `MIC_MUTE` | панель: вимкнення мікрофона | `A1` |
| `WEB` | панель: WEB | `A3` |
| `PANEL_EXTRA` | кнопка панелі, не визначена | `22` |
| `PANEL_KNOB_PRESS` | натискання ручки живлення на панелі | `16` (той самий код, що й `MUTE`) |
| `NEXT` / `PREV` | коліщатко на кермі, одне клацання | `17` / `18` |
| `PANEL_KNOB_UP` / `PANEL_KNOB_DOWN` | ручка панелі, одне клацання праворуч / ліворуч | `81` / `82` |

Статус: **виміряно** (measured). Коди — це те, що CAN-адаптер Simple Soft надсилав магнітолі для
кожної кнопки, записане разом із шиною CAN на спільній шкалі часу (записи `can_20261111_190817.log` і
`can_20261111_191045.log` у `firmware/test_data/captures/`; джерело кожної константи в
`radios/xp-simple-soft/provenance.md`). Кнопку, що надсилає кадр `0A2` (`SOURCE`), у нотатках
еталонного автомобіля описано двома способами («SRC» і «кнопка між SRC і LIST»); її треба ще раз
перевірити в автомобілі.

Якщо у вашому автомобілі є кнопка без відповідної назви, нову назву можна додати до
`enum class KeyId` у `firmware/lib/core/vehicle_signals.h`, **лише в кінець списку**, щоб номери
наявних назв лишилися тими самими. Їй також потрібен код у протоколі магнітоли, інакше вона
ніколи не надсилається.

## Типові перепризначення беруться з профілю автомобіля {#default-remappings-come-from-the-car-profile}

Безпосередньо перед тим, як кадр кнопки йде до магнітоли, прошивка застосовує невелику таблицю
перепризначень (`firmware/lib/radio_xp/xp_keys_custom.h`). Її початкові записи беруться з профілю
автомобіля (поля `keyRemapDefaults` і `keyRemapDefaultCount`, див. [Напишіть профіль автомобіля](write-a-profile.md)).
В еталонному профілі `psa_aee2010` їх два, вибрані для еталонного автомобіля та його магнітоли:

| З | На | Чому (виміряно: тест автора в автомобілі, одна магнітола) |
|---|---|---|
| `9F` (`TEL`) | `9B` | відкриває екран телефону; `9F` без підключеного телефону нічого не робив |
| `21` (`SOURCE`) | `1F` | голосовий помічник (Siri у CarPlay) |

Це вподобання власника, а не факти про шину: в іншому автомобілі цих кнопок може не бути.
Профілі `generic` і `example` не мають типових записів, як і профіль, скопійований із шаблону, тож
кожна кнопка доходить до магнітоли зі своїм кодом. Тест шаблону це показує:
`[key] code=21 state=1` (SRC іде як `21`).

Щоб мати типове перепризначення у власному профілі, додайте рядок до його таблиці
`keyRemapDefaults`. Щоб прибрати його в працюючому пристрої, використайте `map 21 21` у консолі USB
або розділ «Перепризначення кнопок» веб-панелі.

Кнопка місяця (`A4`) обробляється окремо від таблиці (засувка прив'язана до коду, який протокол
магнітоли дає `MOON`, у XP це `A4`, а не до будь-якої кнопки, якій випадково дістався цей код): перше натискання надсилає лише «натиснуто»
(магнітола гасить екран), друге — лише «відпущено». Перепризначення для `A4` не діє.

## Змініть призначення без перезбирання {#change-a-mapping-without-rebuilding}

Команди консолі USB ([Консоль USB](../../en/reference/console.md)):

| Команда | Що вона робить |
|---|---|
| `map` | перелічує таблицю, наприклад `[key] swap 9F -> 9B` |
| `map FROM TO` | код кнопки `FROM` надсилає магнітолі `TO`, обидва шістнадцяткові: `map 9B 1F`. `map 9B 9B` видаляє запис |
| `map reset` | повернення до типових записів профілю автомобіля (у `generic` їх немає) |
| `keys` | вмикає або вимикає виведення кожної події кнопки (`[key] printing=1` / `0`) |

Таблиця вміщує не більше 16 записів і зберігається в налаштуваннях пристрою, тож переживає
перезапуск. Веб-панель редагує ту саму таблицю.

`FROM` — це код, який протокол магнітоли дає кнопці (третій стовпець вище), а не значення CAN.

## З'ясуйте, що робить код у вашій магнітолі {#find-out-what-a-code-does-in-your-radio}

У збірці декодера можна надіслати магнітолі будь-який код кнопки з консолі USB, не торкаючись
автомобіля:

| Команда | Що вона надсилає |
|---|---|
| `key 1F` | код `1F` натиснуто, потім відпущено |
| `kd A4` | лише «натиснуто» |
| `ku A4` | лише «відпущено» |

У збірці лише прослуховування консоль відповідає `: not sent (listen mode)`, і нічого не
виходить.

Що деякі коди робили в магнітолі еталонного автомобіля, перевірено через `key` (виміряно: тест
автора, одна магнітола, профіль CAN «XP Simple Soft -> Peugeot 508 -> Type 2»):

| Код | Реакція |
|---|---|
| `08` | зміна джерела |
| `1F` | голосовий помічник (Siri у CarPlay) |
| `9A` | яскравість екрана |
| `9B` | телефон |
| `A5` | екран клімат-контролю |
| `A6` | назад |
| `B5` | FM / AM |
| `B9`, `BF` | обидва: настроювання вниз на 0.05 MHz (два коди з однаковою нотаткою; перевірити ще раз) |
| `B1`, `91`–`96` | без реакції |

Інша магнітола або інший профіль CAN у налаштуваннях магнітоли можуть реагувати інакше.
Спробуйте кожен код на своїй магнітолі й запишіть, що він зробив.

## Що ще йде до магнітоли з вашим профілем {#what-else-goes-to-the-radio-with-your-profile}

З протоколом XP і профілем, відмінним від еталонного, магнітола отримує лише такі кадри
(виміряно: тест на комп'ютері для профілю-шаблону, `firmware/test_host/expected/example_car.txt`):

| Команда XP | Вміст | З вашого профілю |
|---|---|---|
| `EA` | стан живлення (ACC) | `decodeBody` (запалювання) |
| `20` | кнопка | `keys`, `knobs` |
| `32` | зображення парктроніків | `decodeParking` |
| `3E` | прапорець перешкоди | `decodeParking` |

Дані автомобіля для екрана магнітоли надходять з необов'язкових функцій вашого профілю:

- `38` двері та значення налаштувань: `decodeDoors`, `decodeSettings`;
- `3C` які рядки налаштувань показувати: `decodeSettings`;
- `33`, `34`, `35` сторінки бортового комп'ютера: `decodeTrip`;
- `36` зовнішня температура: `decodeOutsideTemp`;
- `44` економний режим: `decodeEcoMode`;
- `21` стан клімат-контролю: `decodeClimate`;
- `29` кут повороту керма: `decodeSteering`.

Кадр, функція якого у вашому профілі дорівнює `nullptr`, ніколи не надсилається. Кодувальники XP
містяться у `firmware/lib/radio_xp/xp_signals.h`. Зміна налаштувань автомобіля з магнітоли
(команда `80`) працює лише з еталонним профілем.

Далі: [Контрольний список перенесення](porting-checklist.md).
