# Прошивка

> [!NOTE]
> **Машинный перевод, требует проверки**
>
> Эта страница переведена автоматически. Обязательным является английский текст. Как прислать
> исправление перевода: [Переводы](../../en/contributing/translations.md#send-your-work).

Эта страница проведёт вас от чистого компьютера до платы, на которой работает прошивка и
открывается её веб-панель. Для шагов 1-3 плата не нужна.

> [!NOTE]
> **Состояние этого дерева прошивки**
>
> Эта прошивка собирается и проходит тесты на ПК (все окружения собираются, тесты на компьютере
> совпадают с эталонами). Версия 2.0.0 проверена на плате ESP32-S3-WROOM-1-N16R8 по
> [протоколу проверки на стенде](../../en/testing/bench-test-protocol.md) и опробована в одном
> автомобиле 20.11.2026.

**Где вводить команды.** В Windows вводите все команды этой страницы в **PowerShell** (или в
Windows Terminal). Git Bash для прошивки не нужен, только для тестов на компьютере и для страниц
раздела [Под свой автомобиль](../make-it-yours/porting-checklist.md). В Linux и
macOS используйте обычный терминал.

## Быстрее всего: готовый образ в браузере {#ready-image-in-the-browser}

Это рекомендуемый способ для первой установки. Не нужны ни PlatformIO, ни пакет Python для
прошивки, ни обычно дополнительный драйвер: только Chrome или Edge и файл образа. Способ работает и
там, где `pip install esptool` не проходит (на очень новой версии Python установка может
остановиться ошибкой сборки одной из зависимостей).

1. Скачайте образ. Готовые образы лежат на странице проекта в разделе **Releases**, по паре на
   каждое окружение без передачи в CAN (`listen`, `decoder`, `listen_wifi`, `decoder_wifi`,
   `listen_generic_wifi`; прочитайте [Какое окружение](#which-environment)). Образа с передачей в
   готовом виде нет никогда. Выберите файл по задаче:

    | Файл | Адрес | Для чего |
    |---|---|---|
    | `<environment>-<version>-merged.bin` | `0x0` | первая установка; стирает всю flash-память вместе с сохранёнными настройками (потом устройство создаст новый пароль Wi-Fi) |
    | `<environment>-<version>.bin` | `0x10000` | обновление устройства, на котором уже работает эта прошивка; сохранённые настройки остаются |

    Собственная сборка (шаги 1-3 ниже) даёт образ приложения
    `.pio/build/<environment>/firmware.bin`: как и файл без `-merged`, он записывается по адресу
    `0x10000` и только обновляет устройство, на котором уже работает эта прошивка.

2. Подключите плату к компьютеру USB-кабелем для данных, в собственное гнездо USB микросхемы
   ESP32-S3 (см. [Подключите плату](#4-connect-the-board)).
3. Откройте <https://espressif.github.io/esptool-js/> в Chrome или Edge.
4. Нажмите **Connect** и выберите порт платы в списке, который покажет браузер.
5. Введите адрес из таблицы в поле адреса, рядом выберите файл образа и нажмите **Program**.
   Кнопки на модуле не нужны: плата перезагружается сама.
6. Ожидаемо: журнал на странице заканчивается строкой `Hash of data verified.` Если новая
   программа не запустилась, нажмите RESET или переподключите кабель.

Консоль на той странице только показывает, что выводит устройство; вводить команды в ней нельзя.
Чтобы вводить команды, один раз установите небольшой последовательный терминал Python и запустите
его (в Linux и macOS вводите `python3` вместо `python`):

```text
python -m pip install pyserial
python -m serial.tools.miniterm - 115200
```

`-` заставляет его показать список портов; выберите плату. Вводимые символы не отображаются:
вводите команду вслепую и завершайте её Enter. Выход из терминала: Ctrl+].

После первой установки `ver` показывает версию. Сборка с сетью затем открывает свою сеть Wi-Fi
`<project name>-XXXX` с панелью по адресу `http://10.50.8.1`, не больше чем для четырёх устройств
одновременно. Дальше перейдите к [Первый запуск](first-boot.md#2-read-the-password-from-the-usb-console),
чтобы прочитать пароль.

<details class="note" markdown="1">
<summary>Другой путь: esptool в командной строке</summary>

Если `esptool` устанавливается на вашем компьютере, он записывает те же файлы по тем же адресам.
Используйте одну из двух команд записи:

```text
python -m pip install esptool
python -m esptool --chip esp32s3 write-flash 0x0 <environment>-<version>-merged.bin
python -m esptool --chip esp32s3 write-flash 0x10000 <environment>-<version>.bin
```

</details>

**Собрать самому.** Пронумерованные шаги ниже собирают прошивку из исходного кода в PlatformIO
и загружают её по USB. Используйте их, если для вашей задачи нет готового образа или если вы
меняете код.

## 1. Установите uv {#1-install-uv}

Прошивка собирается с помощью [PlatformIO](https://platformio.org/). Устанавливать его сами вы не
будете: `uvx platformio ...` скачивает и запускает его через [uv](https://docs.astral.sh/uv/) —
небольшую программу для запуска инструментов.

### Windows {#windows}

1. Откройте PowerShell и выполните:

    ```powershell
    winget install --id=astral-sh.uv -e
    ```

2. Закройте PowerShell и откройте его снова, чтобы он нашёл `uv`.

Для прошивки не нужно; нужно для тестов на компьютере и для раздела «Под свой автомобиль»:
[Git for Windows](https://git-scm.com/download/win). С ним приходит **Git Bash**, который запускает
тестовые скрипты и команды этих страниц.

### Linux {#linux}

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Чтобы работать с портом USB без root, добавьте себя в группу последовательных портов (`dialout`
в Debian и Ubuntu, `uucp` в Arch) и установите правила udev для PlatformIO, как описано в
[документации PlatformIO](https://docs.platformio.org/en/latest/core/installation/udev-rules.html).
Выйдите из системы и войдите снова.

### macOS {#macos}

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

или через Homebrew: `brew install uv`.

### Проверка {#check-it}

Откройте новый терминал и выполните:

```text
uvx platformio --version
```

Ожидаемый результат: одна строка с версией PlatformIO, например `PlatformIO Core, version 6.2.0`.
Первый вызов скачивает PlatformIO и занимает немного времени; следующие запускаются сразу.
Если видите «command not found» или «not recognized», закройте терминал, откройте новый и
попробуйте ещё раз.

Если вам удобнее редактор, подойдёт и расширение PlatformIO для VS Code: откройте папку
`firmware` и выберите окружение в строке состояния. Команды ниже — это то, что расширение
выполняет за вас.

## 2. Получите код {#2-get-the-code}

1. Откройте страницу проекта (репозиторий, где вы нашли это руководство) и выберите
   **Code → Download ZIP**. Если вы пользуетесь Git, подойдёт и `git clone`.
2. Распакуйте ZIP. В Windows: правый щелчок по файлу → **Извлечь всё**.
3. Откройте распакованную папку, в которой рядом видны `firmware`, `docs` и `README.md`. После
   распаковки она часто лежит на уровень глубже, в папке с тем же именем.
4. Откройте терминал в папке `firmware` внутри неё:
    - **Windows:** откройте `firmware` в Проводнике, щёлкните по адресной строке, введите
      `powershell` и нажмите Enter. (В Windows 11 подойдёт и правый щелчок по пустому месту →
      **Открыть в Терминале**.)
    - **Linux и macOS:** откройте терминал, введите `cd ` (с пробелом), перетащите папку
      `firmware` в окно и нажмите Enter.

Все команды ниже выполняются в этом терминале, в папке `firmware`.

## 3. Сборка {#3-build}

```text
uvx platformio run -e listen_wifi
```

Эта программа только слушает автомобиль и имеет веб-панель. Без панели используйте здесь и в
шаге 5 `-e listen`.

Первая сборка скачивает платформу ESP32 (`espressif32@8.0.0`, закреплена в `platformio.ini`) и
компилятор. Это большая загрузка, она может занять много минут; не прерывайте её. Следующие
сборки используют её повторно.

Ожидаемый результат: в конце PlatformIO выводит `SUCCESS`. Программа лежит в
`.pio/build/listen_wifi/firmware.bin`. Если вместо этого видите `Error`, прочитайте первую строку
ошибки: ошибка сети означает, что загрузка прервалась; выполните команду ещё раз.

### Какое окружение {#which-environment}

**Окружение** — это именованный набор параметров сборки в `firmware/platformio.ini`. Оно
определяет, что устройству разрешено делать. На столе достаточно `listen_wifi`. Для другого
автомобиля, не эталонного, позже используйте `listen_generic_wifi`.

<details class="note" markdown="1">
<summary>Все шесть окружений и сборка всех сразу</summary>

Никогда не меняйте режим правкой `src/config.h`; вместо этого выберите окружение.

| Окружение | Режим | Панель Wi-Fi и обновления по Wi-Fi | Передаёт в шину автомобиля | Для чего |
|---|---|---|---|---|
| `listen` (по умолчанию) | параллельный режим (рядом с адаптером) | нет | нет (в программе нет кода передачи) | первая прошивка, стенд, прослушивание рядом с CAN-адаптером |
| `decoder` | декодер | нет | нет | замена CAN-адаптера, без сети |
| `listen_wifi` | параллельный режим | да | нет | прослушивание с веб-панелью |
| `decoder_wifi` | декодер | да | нет | замена CAN-адаптера, с веб-панелью |
| `decoder_tx_wifi` | декодер | да | **только кадр `15B`, после `cantx on` и перезапуска** | изменение персональных настроек с экрана магнитолы; сначала прочитайте [Передача в шину CAN](../../en/safety/transmit.md) |
| `listen_generic_wifi` | параллельный режим | да | нет | другой автомобиль: профиль `generic`, магнитола `none`, записывает шину и ничего не отправляет магнитоле |

«Параллельный режим» (рядом с адаптером) — это режим только прослушивания: устройство
работает рядом с CAN-адаптером и ничего не отправляет. Консоль называет этот же режим
`alongside the box`.

Просто `uvx platformio run` (без `-e`) собирает `listen` — безопасный режим без сети.

Чтобы собрать все шесть окружений сразу, выполните `make build` в корневом каталоге (нужен
`make`, которого нет в Git Bash; обычные команды `uvx platformio run -e ...` работают
всегда).

Необязательные настройки, которые остаются на вашем компьютере, кладутся в
`firmware/platformio_override.ini` (скопируйте `platformio_override.sample.ini`). Образец
показывает свою плату (`listen_mine`) и свой профиль автомобиля (`listen_mycar`). Пробный
кадр `1A9` появляется, только если вы намеренно добавите там
`-DCAN_TX_EXPERIMENTAL=1` к сборке с передачей.

</details>

> [!WARNING]
> **Режим декодера только без CAN-адаптера**
>
> Прошивайте окружение `decoder*`, только когда покупной CAN-адаптер отключён, или на стенде.
> Два устройства на линии данных магнитолы и два источника на проводе ACC замыкают выходы
> друг друга.

## 4. Подключите плату {#4-connect-the-board}

1. Подключите плату к компьютеру кабелем USB, который передаёт данные (не кабелем только для
   зарядки). На платах с двумя гнёздами USB используйте то, которое соединено с самим ESP32-S3
   (часто подписано `USB`, а не `UART`): эта прошивка работает через встроенный USB микросхемы.
2. Посмотрите список портов:

    ```text
    uvx platformio device list
    ```

Ожидаемый результат: после подключения платы появляется новая строка. Windows 10 и 11 обычно не
требуют дополнительного драйвера для этого порта.

| Система | Порт выглядит так |
|---|---|
| Windows | `COM5` (любой номер) |
| Linux | `/dev/ttyACM0` |
| macOS | `/dev/cu.usbmodem1101` (любой номер) |

Ничего нового в списке? Попробуйте другой кабель. Если порта по-прежнему нет, запустите
загрузчик вручную, см.
[Если загрузка не начинается](#if-the-upload-does-not-start-bootloader-mode).

## 5. Загрузка {#5-upload}

```text
uvx platformio run -e listen_wifi -t upload
```

PlatformIO находит порт сам. Если подключено несколько плат, укажите его:
`uvx platformio run -e listen_wifi -t upload --upload-port COM5`.

Ожидаемый результат: загрузка заканчивается `[SUCCESS]`.

- «could not open port» или «Access is denied»: порт занят. Закройте монитор (Ctrl+C) в другом
  окне и запустите загрузку ещё раз.
- Порт не найден: попробуйте другой кабель, затем режим загрузчика ниже.

Загрузка через USB сохраняет записанные настройки (громкость, таблицу кнопок, пароль Wi-Fi).

### Если загрузка не начинается: режим загрузчика {#if-the-upload-does-not-start-bootloader-mode}

Обычно программа загрузки сама перезапускает ESP32-S3 во встроенный загрузчик через USB. Если
порт не появляется или загрузка обрывается с ошибкой соединения (например, после программы,
которая падает при старте), запустите загрузчик вручную:

1. Удерживайте кнопку **BOOT** (на некоторых платах подписана `0` или `IO0`).
2. Нажмите и отпустите **RESET** (`RST` или `EN`) или подключите кабель USB, удерживая BOOT.
3. Отпустите BOOT. Порт снова появится; выполните команду загрузки.
4. После загрузки один раз нажмите RESET, чтобы новая программа запустилась.

Это кнопки отладочной платы ESP32-S3, а не несущей платы.

## 6. Смотрите консоль {#6-watch-the-console}

```text
uvx platformio device monitor
```

Скорость (115200) берётся из `platformio.ini`. Нажмите RESET на плате, чтобы увидеть стартовые
строки. Они выглядят так (первая строка начинается с названия проекта; `listen` выводит
`network=no`, `listen_wifi` — `network=yes`):

```text
# <project name>. CAN 125 kbit/s LISTEN ONLY. Mode: alongside the box (sends nothing).
# profile: car=psa_aee2010 radio=xp
# version: <product> 2.0.0, built <date and time>, network=yes, volume=40%
# can=ok audio=ok radio=ok
# start: <reset reason>
```

RESET также на мгновение отключает порт USB. Если монитор остановился или вы пропустили
стартовые строки, запустите монитор снова и введите `ver`.

> [!NOTE]
> **Вводимые символы не видны**
>
> Буквы, которые вы вводите, на экране не появляются. Это нормально: прошивка не возвращает их
> обратно. Введите команду вслепую и нажмите Enter; ответ появится на новой строке.

Введите `help` и Enter, чтобы получить список команд, `ver` — версию, `stat` — состояние.
Выйти из монитора: Ctrl+C.

`FAIL` в строке `can=... audio=... radio=...` означает, что драйвер не запустился. Тогда
устройство остаётся в безопасном состоянии (выходы 12 В выключены, ничего не отправляется), а
светодиод на плате горит красным. В цикл перезапусков оно не уходит.

## Полная очистка {#erasing-everything}

`uvx platformio run -e listen -t erase` стирает всю флеш-память, включая записанные настройки.
При следующем запуске сети создаётся новый пароль Wi-Fi. После этого снова загрузите программу.
