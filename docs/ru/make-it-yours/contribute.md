# Поделитесь своим автомобилем

> [!NOTE]
> **Машинный перевод, требует проверки**
>
> Эта страница переведена автоматически. Обязательным является английский текст. Как прислать
> исправление перевода: [Переводы](../../en/contributing/translations.md#send-your-work).

Вы измерили автомобиль, которого нет в `vehicles/SUPPORTED.md`. Ваши заметки помогут следующему
человеку с таким же автомобилем, даже без профиля прошивки. Здесь описано, чем делиться,
как сначала очистить данные и куда кладётся каждый файл. Общие правила вклада — в `CONTRIBUTING.md` в
корне репозитория.

Это любительский проект с одним сопровождающим. Ответ или проверка в какой-либо срок не
обещаются.

## Чем можно поделиться {#what-you-can-share}

| Вклад | Куда кладётся |
|---|---|
| Описание автомобиля и его шины | `vehicles/<make>-<model>-<year>/README.md`, по образцу `vehicles/_template/README.md` |
| Кадры и сигналы | `vehicles/<make>-<model>-<year>/<car>.dbc`, каждый комментарий начинается со статуса |
| Виды разъёмов и таблицы контактов | `vehicles/<make>-<model>-<year>/wiring.md`, с указанием стороны, с которой вы смотрели |
| Записи, используемые тестом | `firmware/test_data/captures/`, с одной строкой в его `README.md` |
| Профиль прошивки | `firmware/lib/car_<name>/` ([Напишите профиль автомобиля](write-a-profile.md)) |
| Его хост-тест | `firmware/test_host/<name>_car.cpp`, эталон в `firmware/test_host/expected/`, один блок в `firmware/tools/run_host_tests.sh` ([Проверьте свой профиль](test-your-profile.md)) |
| Что ваша магнитола делает с каждым кодом кнопки | страница вашего автомобиля, раздел "Radio side" ([Сопоставление с магнитолой](radio-mapping.md)) |
| Строка для списка поддерживаемых | `vehicles/SUPPORTED.md`: автомобиль, профиль, статус, что работает, ссылка на вашу страницу |

Pull request только со страницей автомобиля приветствуется. Issue с шаблоном "New vehicle" тоже,
если вы не пользуетесь Git.

## Правила для фактов {#the-rules-for-facts}

- У каждого факта есть статус: **измерено** (measured; чем: мультиметр, запись, консоль устройства;
  для записи — файл и шаг) или **не проверено** (unverified; источник: открытая база данных,
  форум, чертёж продавца).
- Вывод — не измерение. "Напряжения похожи на низкоскоростную отказоустойчивую CAN" — это вывод; скажите,
  что его подтвердило бы.
- Пишите только то, что видели. "Не измерено" — хорошая запись.
- Только ваша собственная работа: ваши записи, фото и слова. Не присылайте декомпилированный код,
  прошивки или приложения производителей адаптеров или магнитол, взятые из них таблицы, даташиты
  или код, скопированный из проектов с несовместимой лицензией. Вместо копирования дайте ссылку на
  открытый источник.

## Сначала очистите записи {#clean-your-recordings-first}

Запись шины может содержать VIN вашего автомобиля и показывает, когда и как вы ездили. Очистите
каждый файл, прежде чем он покинет ваш компьютер.

### 1. Найдите кадры, в которых есть VIN {#1-find-the-frames-that-carry-the-vin}

На эталонном автомобиле VIN находится в кадрах `336`, `3B6` и `2B6` (измерено: записи эталонного
автомобиля). Эти три ID — значения по умолчанию инструмента очистки и `record.py`. **У другой
марки VIN может быть в других кадрах или вообще не на этой шине.** Выясните это, прежде чем
делиться:

1. Возьмите VIN из регистрационного документа. Не вписывайте его ни в один файл, которым будете
   делиться.
2. VIN — это 17 букв и цифр. Переведите первые три символа в шестнадцатеричные коды ASCII:
   например, `V` = `56`, `F` = `46`, `3` = `33`.
3. Найдите эти байты в своей записи текстовым редактором, а затем шестнадцатеричные коды остальных
   символов. Любой кадр, данные которого складываются в часть VIN, — кадр VIN. В виде текста
   17 символов не помещаются в один 8-байтовый кадр, поэтому ждите больше одного. Если ничего не
   совпадает, автомобиль, возможно, не отправляет VIN текстом по этой шине; напишите об этом на
   странице автомобиля.
4. Запишите ID. Если ни одного не нашли, напишите на странице автомобиля "VIN frames: none found".

### 2. Перезапишите их {#2-overwrite-them}

Из корня репозитория:

```bash
python -I tools/sanitize_capture.py my_drive.log my_drive_clean.log --ids 336,3B6,2B6,ABC
python -I tools/sanitize_capture.py --check my_drive_clean.log --ids 336,3B6,2B6,ABC
```

Замените `ABC` на ID своих кадров VIN (три значения по умолчанию оставьте; вреда от них нет).
Инструмент перезаписывает данные этих кадров нулями той же длины: число строк, время, ID и длины
остаются прежними, поэтому тесты продолжают работать. Ещё он заменяет строку заголовка, в которой
названо имя вашего последовательного порта, на `# capture`. `--check` должен сообщить
`0 problem(s)`.

### 3. Прочитайте комментарии сами {#3-read-the-comments-yourself}

Инструмент копирует строки комментариев (`# ...`) как есть. В них тексты ваших маркеров. Откройте
файл и поищите имена, места, адреса, имена сетей или что-то ещё личное.

### 4. Проверьте всё, что добавляете {#4-scan-everything-you-add}

```bash
python -I tools/scan_private.py .
```

Он ищет VIN, кадры VIN с данными, адреса электронной почты, пользовательские пути Windows,
MAC-адреса и имена сетей устройства с настоящим суффиксом. Он должен закончиться без ошибок.

> [!WARNING]
> **Сканер знает только формат VIN эталонного автомобиля**
>
> `scan_private.py` распознаёт VIN группы PSA (`VF3` + 14 символов) и кадры VIN PSA. Он не знает
> VIN другой марки и ваши собственные кадры VIN. Шаги 1–3 всё равно выполняете вы.

## Перед тем как открыть pull request {#before-you-open-a-pull-request}

В шаблоне pull request есть чек-лист. Для нового автомобиля важны такие пункты:

| Проверка | Команда | Ожидается |
|---|---|---|
| Записи очищены | `python -I tools/sanitize_capture.py --check <files> --ids ...` | `0 problem(s)` |
| Нет личных данных | `python -I tools/scan_private.py .` | нет ошибок |
| Хост-тесты (из `firmware/`) | `bash tools/run_host_tests.sh` | `All tests match the references.` |
| Слои (из `firmware/`) | `python -I tools/check_layering.py` | `Layering OK.` |
| Ваша сборка (из `firmware/`) | `uvx platformio run -e listen_mycar` | `SUCCESS` |
| Ссылки документации, если вы меняли `docs/` | `python -I tools/check_doc_links.py` | нет мёртвых ссылок |

Ваш `platformio_override.ini` остаётся на вашем компьютере: он не отслеживается. Напишите в pull
request, какое окружение сборки вы использовали для своего автомобиля и пробовали ли прошивку на
плате и в автомобиле.

Не меняйте существующие эталоны тестов (`firmware/test_host/expected/`, `golden/`,
`golden_060/`) в pull request, который добавляет автомобиль. Добавить свой собственный файл
эталона можно.

## Передача не входит во вклад автомобиля {#transmission-is-not-part-of-a-car-contribution}

Профиль, собранный с `-DCAR_PROFILE=CUSTOM`, не может передавать, и в прошивке нет способа добавить
кадр передачи во время работы. Кадру, который устройству разрешено отправлять, нужны собственное
измерение, проверка содержимого, написанная на C++, хост-тест и именованный профиль в
`firmware/src/config.h`. Это отдельное обсуждение, а не часть добавления автомобиля: прочитайте
[Передача в шину CAN](../../en/safety/transmit.md) и сначала откройте issue.
