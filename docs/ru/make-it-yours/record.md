# Запись шины

> [!NOTE]
> **Машинный перевод, требует проверки**
>
> Эта страница переведена автоматически. Обязательным является английский текст. Как прислать
> исправление перевода: [Переводы](../../en/contributing/translations.md#send-your-work).

Запись (capture) — это текстовый файл со всеми кадрами CAN, которые увидело устройство, по порядку
и со временем. Вы делаете её, пока выполняете действия в автомобиле: нажимаете кнопку, открываете
дверь, включаете задний ход. Потом вы ищете биты, которые изменились в эти моменты
([Расшифровка](decode.md)).

Сначала нужны данные со страницы [Найдите свою шину](find-your-bus.md): провода, тип шины и
скорость.

> [!CAUTION]
> **Записывайте сборкой только для прослушивания**
>
> Используйте `listen_generic_wifi` или отдельный сниффер из `extras/sniffer/`. Оба только
> слушают. Не записывайте неизвестный автомобиль сборкой, которая может передавать.

## Формат {#the-format}

Одно событие на строку, один и тот же формат во всём проекте:

```
(416.094276) can0 532#0800000000000000      CAN frame: time in s, interface, ID#DATA
(12.346900) uartA FD04021117                UART bytes (only the sniffer's recorder variant)
# STEP 3 19:06:41.149 Volume + three times   comment line: a marker
# stat rx=30529 ...                          comment line: statistics
```

Строки, которые начинаются с `#`, — комментарии. Некоторые комментарии — **маркеры**: строки,
которые вы добавляете во время записи, в момент начала действия. Именно маркеры делают запись
удобной для расшифровки. Каждый инструмент пишет маркеры своего вида:

| Инструмент | Строка маркера |
|---|---|
| `record.py` | `# MARKER n (time) computer clock HH:MM:SS: text` |
| `record_serial.py` (сниффер) | `# STEP n HH:MM:SS.mmm text` (Enter), `# MARK d HH:MM:SS.mmm` (цифра от `1` до `9` + Enter) |

Подробнее о формате: [Записи с автомобиля](../../en/testing/captures.md).

## Выберите инструмент {#choose-a-tool}

- Используйте `firmware/tools/record.py`, если у вас устройство с `listen_generic_wifi` и ноутбук
  в его сети Wi-Fi. Файл попадает в папку `logs` рядом с папкой репозитория.
- Используйте `extras/sniffer/record_serial.py`, если у вас отдельная плата сниффера по USB. Файл
  попадает в папку, указанную в `--out`.
- Используйте `dump` в консоли USB только для быстрого взгляда: он не пишет маркеров.

## Сначала спланируйте шаги {#plan-the-steps-first}

Запишите шаги до того, как сядете в автомобиль. Хороший план:

- **Начните с нескольких секунд бездействия**, чтобы запись показала автомобиль в покое.
- **Одно действие на шаг.** "Громкость вверх" и "громкость вниз" — два шага.
- **Повторяйте каждое действие три раза**, с паузой от 2 до 3 секунд. Бит, который изменился три
  раза, — ваш сигнал. Бит, который меняется всё время, — счётчик или шум.
- **Ставьте маркер прямо перед действием**, а не после него.
- **Отмечайте состояние автомобиля** в начале каждого шага: зажигание, двигатель, двери, что
  показывает магнитола.

Пример плана на английском — `extras/sniffer/scenarios/example_buttons.txt`. Он начинается так:

```
START: ignition off, key out, radio off, wait 10 s
Insert the key, ignition on (engine off), wait until the radio has started, then 10 s
Steering wheel: volume + three times, every 2 s
Steering wheel: volume - three times, every 2 s
```

Записи эталонного автомобиля в `firmware/test_data/captures/` сделаны по таким планам. Строки шагов
в них на польском (`# KROK n` = "шаг n") и оставлены как были записаны.

## Запись по Wi-Fi с `record.py` {#record-over-wi-fi-with-recordpy}

1. Соберите и прошейте `listen_generic_wifi` с найденной скоростью: из папки `firmware`,
   `uvx platformio run -e listen_generic_wifi -t upload` ([Прошивка](../quick-start/flash.md)).
2. Подключите устройство к автомобилю ([Подключение к CAN](../../en/install-in-car/can-connection.md)).
3. Подключите ноутбук к сети Wi-Fi устройства ([Первый запуск](../quick-start/first-boot.md)).
   Ноутбук должен работать от батареи или от питания автомобиля.
4. Из папки репозитория выполните:

    ```
    python -I firmware/tools/record.py
    ```

    Адрес по умолчанию — `10.50.8.1`. Другой адрес указывается первым аргументом.
5. Когда спросят, введите пароль устройства. Это тот же ключ, что и у сети Wi-Fi; его показывает
   `wifi showpass` в консоли USB ([Первый запуск](../quick-start/first-boot.md)). Он не
   отображается на экране и не сохраняется.
6. Дождитесь `[ok] connected, recording`. Скрипт выведет имена двух файлов: один с кадрами CAN,
   другой со строками консоли устройства.
7. Для каждого шага: введите короткий текст (например, `volume up 3x`), нажмите Enter, затем
   выполните действие.
8. Чтобы остановить, введите `q` и Enter.

`record.py` только читает с устройства. Он не отправляет команд и ничего не меняет. Кадры `336`,
`3B6` и `2B6` записываются как `# masked`, потому что на эталонном автомобиле в них VIN. В вашем
автомобиле VIN может быть в других кадрах: найдите их, прежде чем чем-то делиться
([Поделитесь своим автомобилем](contribute.md)).

> [!WARNING]
> **`record.py` всегда скрывает `336`, `3B6` и `2B6`**
>
> В другом автомобиле эти три ID могут нести обычные сигналы, а у скрипта нет настройки, чтобы
> их сохранить. Если не можете найти сигнал, сделайте одну запись сниффером или через `dump`:
> оба сохраняют все кадры, поэтому очистите такой файл, прежде чем им делиться.

Если связь по Wi-Fi пропадает, скрипт продолжает попытки. Кадры, которые устройство не смогло
передать, записываются как `# lost N frames`. Устройство хранит в памяти около 9 с кадров, поэтому
при коротких обрывах ничего не теряется.

> [!NOTE]
> **Не записывайте в веб-панели**
>
> Просмотр CAN в веб-панели записывает, только пока его вкладка в браузере видна. Когда автор во время
> записи в панели переключился на другую вкладку, потерялось 26 593 кадра (измерено (measured):
> строка `# zgubiono 26593 ramek`, по-польски "потеряно 26593 кадра", в
> `centralka_can_20261117_184411.log`). Используйте `record.py`.

## Запись по USB сниффером {#record-over-usb-with-the-sniffer}

Сниффер — небольшая отдельная программа для платы ESP32-S3 с модулем трансивера CAN и вообще без
провода передачи. Сборка, подключение и команда записи описаны в `extras/sniffer/README.md`.
Коротко:

```
uv run --with pyserial python -I extras/sniffer/record_serial.py COM7 --scenario extras/sniffer/scenarios/example_buttons.txt
```

Запускайте его из папки репозитория. Вместо `COM7` укажите свой порт: его показывает
`uvx platformio device list`. Скрипт показывает следующий шаг сценария. Нажмите Enter, когда
начинаете его.

## Как маркеры получают время {#how-markers-get-their-time}

У строки комментария нет своего времени. Инструмент расшифровки ([Расшифровка](decode.md)) даёт
каждому маркеру время первого кадра CAN после него. Маркер от `record.py` несёт в скобках время
устройства, и тогда используется оно.

Это важно, когда шина спит. В эталонной записи `can_20261110_190421.log` шина молчала во время
первых двух шагов ("старт, ждать 10 с" и "зажигание включено"). Оба маркера получили одно и то же
время — момент пробуждения шины:

```
    1  line     21     397.922 s  # KROK 1 19:04:37.265 START: zaplon OFF, kluczyk wyjety, drzwi zamkniete, czekaj 10 s (magistrala w spoczynku)
    2  line     39     397.922 s  # KROK 2 19:04:54.247 Wloz kluczyk i wlacz zaplon (bez odpalania), czekaj 10 s
```

Поэтому для шага "зажигание включено" смотрите на первые кадры записи, а не на изменение около
маркера.

## После записи {#after-the-recording}

- Проверьте числа, которые скрипт выводит в конце: кадры, маркеры, потерянные кадры.
- Откройте файл в текстовом редакторе и прочитайте строки комментариев. Тексты ваших маркеров
  копируются в файл без изменений: не вводите в них ничего личного.
- Сохраните исходный файл. Работайте с копией.
- Прежде чем поделиться записью с кем-либо, удалите VIN и проверьте файл
  ([Поделитесь своим автомобилем](contribute.md)).

Далее: [Расшифровка кадров](decode.md).
