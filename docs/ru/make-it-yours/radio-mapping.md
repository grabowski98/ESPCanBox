# Сопоставление с магнитолой

> [!NOTE]
> **Машинный перевод, требует проверки**
>
> Эта страница переведена автоматически. Обязательным является английский текст. Как прислать
> исправление перевода: [Переводы](../../en/contributing/translations.md#send-your-work).

Профиль автомобиля определяет, **какие биты CAN соответствуют какой кнопке**. Протокол магнитолы
определяет, **какой код магнитола получает для этой кнопки**. Между ними — список логических имён кнопок, `KeyId`. Эта
страница объясняет эти три части и то, как изменить действие кнопки в магнитоле, с пересборкой и
без неё.

## Три таблицы {#three-tables}

```text
CAN frame ──► car profile ──► logical button ──► radio protocol ──► key code ──► remapping ──► radio
              keys / knobs      KeyId             keyCode()          e.g. 14       map FROM TO
```

| Часть | Файл | Зависит от |
|---|---|---|
| биты CAN -> `KeyId` | ваш профиль, таблицы `keys` и `knobs` ([Напишите профиль автомобиля](write-a-profile.md)) | автомобиля |
| `KeyId` -> код кнопки | протокол магнитолы, `firmware/lib/radio_xp/protocol_xp.cpp` (`xp::keyCode`) | протокола магнитолы |
| код кнопки -> другой код кнопки | таблица переназначений, во время работы, хранится в настройках устройства | вашего вкуса |

Профиль автомобиля не знает кодов магнитолы, а протокол магнитолы не знает ID CAN.
`tools/check_layering.py` это проверяет.

## Доступные протоколы магнитолы {#radio-protocols-available}

| Флаг сборки | Протокол | Что делает |
|---|---|---|
| `-DRADIO_PROTOCOL=XP` (по умолчанию) | `xp` | протокол CAN-адаптера Simple Soft ("XP") к магнитоле Android на платформе FYT, UART 38400 8N1. Используются только команды, увиденные на линии: [Протокол XP](../../en/reference/xp-protocol.md) |
| `-DRADIO_PROTOCOL=NONE` | `none` | без магнитолы: UART не запускается, ни у одной кнопки нет кода, ничего никогда не отправляется |
| `-DRADIO_PROTOCOL=CUSTOM` | ваш | ваш собственный протокол в `firmware/lib/radio_<имя>`, задаётся через `RADIO_PROTOCOL_CUSTOM_HEADER` и `RADIO_PROTOCOL_CUSTOM_OBJECT` (шаблон: `firmware/lib/radio_example`). На CAN только прослушивание: сборка с передачей останавливается с ошибкой |

`listen_generic_wifi` использует `none`. Ваш собственный профиль с окружением `listen_mycar`
использует `xp`, но в параллельном режиме (рядом с адаптером) в магнитолу всё равно ничего не
отправляется.

> [!NOTE]
> **Других протоколов магнитолы пока нет**
>
> Данные автомобиля для экрана магнитолы (двери, бортовой компьютер, климат-контроль,
> настройки ...) попадают в протокол магнитолы через кодировщики в `RadioProtocol`
> (`firmware/lib/core/radio_protocol.h`), как нейтральные типы. Остальная логика XP (связь
> с магнитолой, кадры парктроников и кнопок, команды от магнитолы) пока зашита внутри декодера.
> Каждый кадр к магнитоле, в том числе от кодировщиков, получает обрамление XP (заголовок `2E`,
> длина, контрольная сумма XP), и кадры XP питания (`EA`), парктроников (`32`), препятствия (`3E`)
> и кнопок (`20`) тоже отправляются: функции обрамления в `RadioProtocol` пока нет. Поэтому новому
> протоколу магнитолы нужны ещё изменения в `firmware/src/config.h` и
> `firmware/lib/app/`. Это есть в планах. Новый протокол должен быть написан по вашим собственным
> измерениям линии к магнитоле, а не по декомпилированным приложениям или прошивкам адаптеров.

## Логические кнопки и коды XP {#logical-buttons-and-xp-codes}

Имена описывают кнопку эталонного автомобиля (Peugeot 508 SW 2015). Для своего автомобиля берите
имя с самым близким смыслом. Код XP — то, что магнитола получает в кадре кнопки `20`
(DATA[0] = код, DATA[1] = 1 нажата, 2 удерживается, 0 отпущена). Это кадр UART: его байты
данных считаются от DATA[0], как на странице [Протокол магнитолы XP](../../en/reference/xp-protocol.md).
Байты CAN на остальных страницах считаются от байта 1.

| `KeyId` | Кнопка на эталонном автомобиле | Код XP |
|---|---|---|
| `VOLUME_UP` | громкость + на руле | `14` |
| `VOLUME_DOWN` | громкость - на руле | `15` |
| `MUTE` | обе кнопки громкости вместе | `16` |
| `PHONE` | кнопка телефона на руле | `30` |
| `LIST` | LIST на руле | `50` |
| `WHEEL_KNOB_PRESS` | нажатие колёсика на руле | `07` |
| `SOURCE` | SRC | `21` |
| `TRIP` | кнопка бортового компьютера на подрулевом переключателе стеклоочистителей | `23` |
| `NAV` | панель: NAV | `9E` |
| `MEDIA` | панель: MEDIA | `A0` |
| `SCROLL_LEFT` | панель: поиск влево | `97` |
| `ZOOM_IN` | панель: масштаб + | `9C` |
| `SCROLL_RIGHT` | панель: поиск вправо | `98` |
| `TEL` | панель: TEL | `9F` |
| `SETUP` | панель: SETUP | `99` |
| `DRIVE` | панель: DRIVE | `9B` |
| `MOON` | панель: выключение экрана (луна) | `A4` |
| `ZOOM_OUT` | панель: масштаб - | `9D` |
| `MIC_MUTE` | панель: отключение микрофона | `A1` |
| `WEB` | панель: WEB | `A3` |
| `PANEL_EXTRA` | кнопка панели, не опознана | `22` |
| `PANEL_KNOB_PRESS` | нажатие ручки питания на панели | `16` (тот же код, что у `MUTE`) |
| `NEXT` / `PREV` | колёсико на руле, один щелчок | `17` / `18` |
| `PANEL_KNOB_UP` / `PANEL_KNOB_DOWN` | ручка панели, один щелчок вправо / влево | `81` / `82` |

Статус: **измерено** (measured). Коды — это то, что CAN-адаптер Simple Soft отправлял магнитоле для
каждой кнопки, записанное вместе с шиной CAN на одних часах (записи `can_20261111_190817.log` и
`can_20261111_191045.log` в `firmware/test_data/captures/`; источник каждой константы в
`radios/xp-simple-soft/provenance.md`). Кнопка, которая отправляет кадр `0A2` (`SOURCE`), описана в
заметках эталонного автомобиля двумя способами ("SRC" и "кнопка между SRC и LIST"); её нужно ещё
раз проверить в автомобиле.

Если у вашего автомобиля есть кнопка без подходящего имени, новое имя можно добавить в
`enum class KeyId` в `firmware/lib/core/vehicle_signals.h`, **только в конец списка**, чтобы номера
существующих имён не изменились. Ему нужен ещё код в протоколе магнитолы, иначе оно никогда не
отправляется.

## Переназначения по умолчанию берутся из профиля автомобиля {#default-remappings-come-from-the-car-profile}

Прямо перед тем, как кадр кнопки уходит в магнитолу, прошивка применяет небольшую таблицу
переназначений (`firmware/lib/radio_xp/xp_keys_custom.h`). Её начальные записи берутся из профиля
автомобиля (поля `keyRemapDefaults` и `keyRemapDefaultCount`, см. [Напишите профиль автомобиля](write-a-profile.md)).
В эталонном профиле `psa_aee2010` их две, выбранные для эталонного автомобиля и его магнитолы:

| Было | Стало | Почему (измерено: проверка автора в автомобиле, одна магнитола) |
|---|---|---|
| `9F` (`TEL`) | `9B` | открывает экран телефона; `9F` без подключённого телефона ничего не делал |
| `21` (`SOURCE`) | `1F` | голосовой помощник (Siri в CarPlay) |

Это предпочтения владельца, а не факты о шине: в другом автомобиле этих кнопок может не быть.
В профилях `generic` и `example` записей по умолчанию нет, как и в профиле, скопированном из
шаблона, поэтому каждая кнопка доходит до магнитолы со своим кодом. Тест шаблона это показывает:
`[key] code=21 state=1` (SRC уходит как `21`).

Чтобы получить переназначение по умолчанию в своём профиле, добавьте строку в его таблицу
`keyRemapDefaults`. Чтобы убрать его в работающем устройстве, используйте `map 21 21` в консоли USB
или раздел переназначения кнопок веб-панели.

Кнопка луны (`A4`) обрабатывается отдельно от таблицы (защёлка привязана к коду, который протокол
магнитолы даёт `MOON`, в XP это `A4`, а не к любой кнопке, которой случайно достался этот код): первое нажатие отправляет только «нажата»
(магнитола гасит экран), второе — только «отпущена». Переназначение для `A4` не действует.

## Изменение сопоставления без пересборки {#change-a-mapping-without-rebuilding}

Команды консоли USB ([Консоль USB](../../en/reference/console.md)):

| Команда | Что делает |
|---|---|
| `map` | выводит таблицу, например `[key] swap 9F -> 9B` |
| `map FROM TO` | код кнопки `FROM` отправляет в магнитолу `TO`, оба в hex: `map 9B 1F`. `map 9B 9B` удаляет запись |
| `map reset` | возврат к записям по умолчанию профиля автомобиля (в `generic` их нет) |
| `keys` | включает или выключает вывод каждого события кнопки (`[key] printing=1` / `0`) |

Таблица вмещает не больше 16 записей и хранится в настройках устройства, поэтому переживает
перезапуск. Веб-панель редактирует ту же таблицу.

`FROM` — это код, который протокол магнитолы даёт кнопке (третий столбец выше), а не значение CAN.

## Узнайте, что делает код в вашей магнитоле {#find-out-what-a-code-does-in-your-radio}

В сборке декодера можно отправить магнитоле любой код кнопки из консоли USB, не трогая автомобиль:

| Команда | Что отправляет |
|---|---|
| `key 1F` | код `1F` нажат, затем отпущен |
| `kd A4` | только «нажата» |
| `ku A4` | только «отпущена» |

В сборке только для прослушивания консоль отвечает `: not sent (listen mode)`, и ничего не уходит.

Реакция магнитолы эталонного автомобиля на некоторые коды, проверенная командой `key` (измерено:
проверка автора, одна магнитола, профиль CAN "XP Simple Soft -> Peugeot 508 -> Type 2"):

| Код | Реакция |
|---|---|
| `08` | смена источника |
| `1F` | голосовой помощник (Siri в CarPlay) |
| `9A` | яркость экрана |
| `9B` | телефон |
| `A5` | экран климат-контроля |
| `A6` | назад |
| `B5` | FM / AM |
| `B9`, `BF` | оба: настройка вниз на 0,05 МГц (два кода с одной и той же заметкой; проверить ещё раз) |
| `B1`, `91` до `96` | без реакции |

Другая магнитола или другой профиль CAN в настройках магнитолы может реагировать иначе.
Попробуйте каждый код на своей магнитоле и запишите, что он сделал.

## Что ещё уходит в магнитолу с вашим профилем {#what-else-goes-to-the-radio-with-your-profile}

С протоколом XP и профилем, отличным от эталонного, магнитола получает только эти кадры
(измерено: хост-тест профиля-шаблона, `firmware/test_host/expected/example_car.txt`):

| Команда XP | Содержимое | Из вашего профиля |
|---|---|---|
| `EA` | состояние питания (ACC) | `decodeBody` (зажигание) |
| `20` | кнопка | `keys`, `knobs` |
| `32` | картинка парктроников | `decodeParking` |
| `3E` | флаг препятствия | `decodeParking` |

Данные автомобиля для экрана магнитолы приходят из необязательных функций вашего профиля:

- `38` двери и значения настроек: `decodeDoors`, `decodeSettings`;
- `3C` какие строки настроек показывать: `decodeSettings`;
- `33`, `34`, `35` страницы бортового компьютера: `decodeTrip`;
- `36` наружная температура: `decodeOutsideTemp`;
- `44` экономичный режим: `decodeEcoMode`;
- `21` состояние климат-контроля: `decodeClimate`;
- `29` угол поворота руля: `decodeSteering`.

Кадр, функция которого в вашем профиле равна `nullptr`, никогда не отправляется. Кодировщики XP
находятся в `firmware/lib/radio_xp/xp_signals.h`. Изменение настроек автомобиля с магнитолы
(команда `80`) работает только с эталонным профилем.

Далее: [Чек-лист переноса](porting-checklist.md).
