# Расшифровка кадров

> [!NOTE]
> **Машинный перевод, требует проверки**
>
> Эта страница переведена автоматически. Обязательным является английский текст. Как прислать
> исправление перевода: [Переводы](../../en/contributing/translations.md#send-your-work).

У вас есть запись с маркерами ([Запись шины](record.md)). Теперь вы ищете биты, которые
изменились, когда вы что-то делали в автомобиле. На этой странице это сделано шаг за шагом на
настоящих записях эталонного автомобиля с помощью инструмента `firmware/tools/can_diff.py`.

Инструмент только читает файлы. Ему нужен Python 3 и больше ничего. Все команды ниже выполняются
из папки репозитория.

Примеры используют записи из репозитория. Ваша собственная запись из `record.py` лежит в папке
`logs` рядом с папкой репозитория, в файле, имя которого заканчивается на
`_can_YYYYMMDD_HHMMSS.log`. Укажите вместо примера путь к нему, например
`python -I firmware/tools/can_diff.py ../logs/<имя файла> --list`.

## Байты и биты {#bytes-and-bits}

У кадра CAN есть ID (три шестнадцатеричные цифры, например `0F6`) и до 8 байтов данных. В этом
проекте они нумеруются так:

- байты с **1**: байт 1 — первый байт данных (`data[0]` в коде C++);
- биты **7..0** внутри байта, бит 0 — младший;
- краткая запись `байт.бит`: `8.7` = байт 8, бит 7.

Пример: в кадре `0F6#884D1E2182585828` байт 1 = `88`, байт 2 = `4D`, ... байт 8 = `28`.

Чтобы увидеть биты, запишите каждую шестнадцатеричную цифру четырьмя двоичными:

| Hex | Двоичный вид (биты 7..0) |
|---|---|
| `24` | `0010 0100` |
| `A4` | `1010 0100` |

`24` и `A4` отличаются только самым левым битом, значит, изменился бит 7.

## Что делает инструмент {#what-the-tool-does}

Для каждого маркера `can_diff.py` сравнивает два окна времени:

- **до**: секунды прямо перед маркером (по умолчанию 3 с, `--before`);
- **после**: секунды сразу после него (по умолчанию 5 с, `--after`).

Он перечисляет все биты, которые были неизменны в окне "до" и изменились в окне "после". Два
фильтра убирают большую часть шума:

- **счётчики**: байт или полубайт, который почти в каждом кадре всей записи меняется на одну и ту
  же величину (циклические счётчики, таймеры). Инструмент выводит их один раз вверху и никогда о
  них не сообщает.
- **фон**: бит, который уже менялся в окне "до", для этого маркера игнорируется ("ignored: N
  background bits" в выводе).

Ещё он перечисляет ID, которые появляются только после маркера ("new IDs"), и ID, которые
пропадают.

Сначала проверьте, что инструмент работает на вашем компьютере. Синтетический файл — выдуманный
автомобиль с известными ответами:

```
python -I firmware/tools/can_diff.py firmware/test_data/synthetic/marker_demo.log --selftest
```

```
selftest: 6 markers, 3216 frames, 0 errors
```

Полезные параметры:

| Параметр | Что делает |
|---|---|
| `--list` | выводит маркеры с номерами и временем, затем останавливается |
| `--marker N` | только маркер N (можно повторять) |
| `--match TEXT` | только маркеры, в тексте которых есть TEXT |
| `--after S`, `--before S` | длина окон в секундах |
| `--id 0F6,21F` | только эти ID |
| `--summary` | для выбранных маркеров: на скольких из них изменился каждый бит |
| `--export OUT` | записывает в OUT только строки CAN, для других программ |

Маркеры — это строки комментариев, которые начинаются с `# STEP`, `# MARK`, `# MARKER` или
`# KROK` (польское слово, использованное в эталонных записях). Другой шаблон задаётся через
`--marker-regex`.

```
python -I firmware/tools/can_diff.py firmware/test_data/captures/can_20261110_190421.log --list
```

```

counters (never reported): 0E6:8H 10B:5L 236:5 3F6:3H
    1  line     21     397.922 s  # KROK 1 19:04:37.265 START: zaplon OFF, kluczyk wyjety, drzwi zamkniete, czekaj 10 s (magistrala w spoczynku)

    3  line   4078     416.094 s  # KROK 3 19:05:19.255 Odpal silnik, 10 s bez ruchu

Строка счётчиков читается так: в `0E6` считает старший полубайт (`H`) байта 8, в `10B` — младший
полубайт (`L`) байта 5, в `236` — весь байт 5, в `3F6` — старший полубайт байта 3. Инструмент
никогда о них не сообщит.

## Пример 1: задний ход (`0F6`) {#example-1-reverse-gear-0f6}

В шаге 17 этой записи по-польски написано: "задний ход: включить на 3 с, выключить, 3 раза (без
препятствия)". Шаг длился около 27 с, поэтому возьмите длинное окно "после":

```
python -I firmware/tools/can_diff.py firmware/test_data/captures/can_20261110_190421.log --marker 17 --after 25
```

Без `--id` инструмент перечисляет 13 ID: `0A1 0B6 0E1 0E6 0F6 10B 128 161 227 236 2AD 3E7 3F6`.
Кадр парктроников `0E1` тоже меняется, а медленные значения плывут за 25 с. Ищите бит, который
меняется **столько раз, сколько вы выполнили действие**. Здесь он в `0F6`:

```
python -I firmware/tools/can_diff.py firmware/test_data/captures/can_20261110_190421.log --marker 17 --after 25 --id 0F6
```

```
==============================================================================
marker 17, line 43732, at 597.094 s
  # KROK 17 19:08:20.249 Wsteczny: wlacz 3 s, wylacz, 3 razy (bez przeszkody)
  window: 3.0 s before, 25.0 s after; ignored: 0 background bits, counters in 0 IDs
  0F6
    byte 2: 51 52
      bits: 2.1 0->1 x1 @+23.87s, 2.0 1->0 x1 @+23.87s
    byte 8: 24 A4 24 A4 24 A4 24 A4
      bits: 8.7 0->1 x7 @+8.67s
```

Как это читать:

- `byte 8: 24 A4 24 ...` — последовательность значений байта, без повторов;
- `8.7 0->1 x7 @+8.67s`: бит 8.7 был 0 до маркера, изменился 7 раз, впервые через 8,67 с после
  маркера.

Бит 8.7 снова и снова переходил в 1 и обратно, в такт с действием. Байт 2 изменился один раз, ближе
к концу: это не действие.

В плане было три раза; в окне бит переходил в 1 четыре раза. Почему — по записи не понять. Доверяйте
тому, что показывает файл, сверяйте со своими заметками и подтверждайте сигнал второй записью.

Результат: задний ход = `0F6` 8.7 (измерено (measured): `can_20261110_190421.log`, шаг 17; тот же
бит есть в `vehicles/peugeot-508-sw-2015/508.dbc`).

## Пример 2: зажигание и двигатель (`0F6` байт 1) {#example-2-ignition-and-engine-0f6-byte-1}

Некоторые сигналы — не один бит, а целый байт с несколькими значениями. В шаге 3 написано "запустить
двигатель, 10 с без движения":

```
python -I firmware/tools/can_diff.py firmware/test_data/captures/can_20261110_190421.log --marker 3 --after 10 --id 0F6
```

```
==============================================================================
marker 3, line 4078, at 416.094 s
  # KROK 3 19:05:19.255 Odpal silnik, 10 s bez ruchu
  window: 3.0 s before, 10.0 s after; ignored: 0 background bits, counters in 0 IDs
  0F6
    byte 1: 88 90 91 89 8A 8E
      bits: 1.4 0->1 x2 @+3.30s, 1.3 1->0 x2 @+3.30s, 1.2 0->1 x1 @+5.02s, 1.1 0->1 x1 @+4.03s, 1.0 0->1 x2 @+3.46s
    byte 8: 20 24 64
      bits: 8.6 0->1 x1 @+6.12s, 8.2 0->1 x1 @+4.07s
```

Здесь список битов запутан, но **значения байта** всё объясняют: `88` до, затем `90 91 89 8A`, пока
крутит стартер, затем `8E` с работающим двигателем. По нескольким записям выключения, включения
зажигания и запуска двигателя эталонный автомобиль даёт `80` выключено, `88` включено,
`90`/`91`/`89`/`8A` прокрутка стартером, `8E` двигатель работает, `86`/`84` выключение (измерено:
записи с шагами зажигания и двигателя, `508.dbc`).

Байт 8 тоже изменился (`20 24 64`). Что значат эти два бита, неизвестно. Не приписывайте биту
смысл только потому, что он изменился в то же время.

Для первого включения окна "до" нет: шина спала, и все ID у маркера "новые" (см.
[Запись](record.md#how-markers-get-their-time)). Тогда читайте первые кадры напрямую. Первый кадр
`0F6` этой записи:

```
(398.212947) can0 0F6#884D1E2182585828
```

Байт 1 = `88`: зажигание включено.

## Пример 3: кнопка на руле (`21F`) {#example-3-a-steering-wheel-button-21f}

Чистый случай. В шаге 3 записи `can_20261111_190817.log` написано "руль: громкость + три раза, каждые
2 с". На этот раз без `--id`:

```
python -I firmware/tools/can_diff.py firmware/test_data/captures/can_20261111_190817.log --marker 3 --after 4.5
```

```
firmware/test_data/captures/can_20261111_190817.log: 30040 frames, 62 IDs, 14 markers, 0 broken lines skipped
counters (never reported): 0E6:8H,8L 10B:5L 236:5 3F6:3H
==============================================================================
marker 3, line 6809, at 223.999 s
  # KROK 3 19:08:54.163 Kierownica: glosnosc + trzy razy, co 2 s
  window: 3.0 s before, 4.5 s after; ignored: 10 background bits, counters in 4 IDs
  21F
    byte 1: 00 08 00 08 00
      bits: 1.3 0->1 x4 @+0.78s
  new IDs (absent before, present after): 1A5(4)
```

Один бит: `21F` 1.3 (байт 1 = `08`, пока кнопка нажата). Окно в 4,5 с вмещает два нажатия из трёх:
4 изменения. Следующий маркер идёт через 4,5 с, поэтому более длинное окно захватило бы следующий
шаг.

Новый ID `1A5` — не от кнопки. В этой записи был подключён покупной CAN-адаптер, и он отправляет
`1A5` (уровень громкости) через несколько миллисекунд после того, как магнитола меняет громкость
(измерено: [Peugeot 508 SW](../../en/reference/vehicles/peugeot-508.md)). Другие устройства на
шине тоже реагируют на ваше действие. Если можете, сделайте одну запись без них.

Результат: громкость вверх = `21F` 1.3 (измерено: `can_20261111_190817.log` и
`can_20261111_191045.log` с линией UART к магнитоле).

## Пример 4: парктроники (`0E1`) {#example-4-parking-sensors-0e1}

Кадр, полный полей. В шаге 18 записи `can_20261111_191045.log` написано "задние датчики: задний ход
включён, приближать предмет к заднему бамперу до непрерывного сигнала, убрать, выключить задний
ход". Этот файл начинается с шага 13, поэтому шаг 18 — это маркер 6 (проверьте через `--list`):

```
python -I firmware/tools/can_diff.py firmware/test_data/captures/can_20261111_191045.log --marker 6 --after 25 --id 0E1
```

  window: 3.0 s before, 25.0 s after; ignored: 2 background bits, counters in 0 IDs
  0E1
    byte 1: B0 B4 90 B0

    byte 2: 00 D0 00 D0 50 D0 00
      bits: 2.7 0->1 x6 @+15.31s, 2.6 0->1 x4 @+15.31s, 2.4 0->1 x4 @+15.31s
    byte 3: 3F 30 2B 3F 2E 28 25 22 ...
      bits: 3.5 1->0 x2 @+16.86s, 3.4 1->0 x6 @+15.51s, 3.3 1->0 x10 @+15.31s, 3.2 1->0 x10 @+15.31s, 3.1 1->0 x14 @+15.31s, 3.0 1->0 x12 @+15.31s
    byte 4: FC F8 F4 F8 F4 F0 EC E8 ...
      bits: 4.7 1->0 x2 @+17.37s, 4.6 1->0 x2 @+17.75s, 4.5 1->0 x4 @+17.37s, 4.4 1->0 x2 @+16.86s, 4.3 1->0 x6 @+15.51s, 4.2 1->0 x10 @+15.31s
    byte 5: FC 5C 3C 1C FC
      bits: 5.7 1->0 x2 @+17.56s, 5.6 1->0 x2 @+17.82s, 5.5 1->0 x4 @+17.56s
```

Когда много соседних битов меняются вместе, это одно поле. Разбейте байты на группы битов,
которые движутся вместе:

| Поле | Где | Что делают значения здесь | Смысл на эталонном автомобиле |
|---|---|---|---|
| состояние сзади, состояние спереди | байт 1, биты 7-5 и 4-2 | `90` = `100 100 00`: сзади 4, спереди 4 | 4 активно, 5 ожидание (измерено) |
| запрос звука | 2.4 | 1, пока автомобиль пищит | измерено |
| стороны | 2.7-2.6 | `D0`: обе стороны | измерено |
| интервал сигналов | байт 3, биты 5-0 | `3F`, затем убывающие значения по мере приближения предмета | `3F` без звука, `39` ... `0B` сигналы, `00` непрерывный сигнал (измерено) |
| зоны датчиков | байты 4-6, по 3 бита | значения убывают по мере приближения предмета | 0 ближе всего ... 7 далеко (измерено) |

Смысл полей: `vehicles/peugeot-508-sw-2015/508.dbc` и
[Peugeot 508 SW](../../en/reference/vehicles/peugeot-508.md#parking-sensors-0e1).

Бит 1.5 тоже изменился (`B4` на `90`), но его нет в списке: он уже двигался в окне "до", которое
перекрывает конец шага с задним ходом. Фоновый фильтр может скрыть настоящий бит. Если вы ждёте бит
и не видите его, сдвиньте окно: с `--before 1` этот запуск показывает и `1.5 1->0 x2`. Значения
байта (`B0 B4 90 B0`) всегда показываются полностью.

## Повторите действие, посчитайте попадания {#repeat-the-action-count-the-hits}

Лучшее доказательство — бит, который меняется у **каждого** маркера одного и того же действия и ни у
какого другого. Если на каждое повторение один маркер, `--match` и `--summary` посчитают это за вас.
На синтетическом файле (выдуманный автомобиль, три открытия двери и три нажатия кнопки):

```
python -I firmware/tools/can_diff.py firmware/test_data/synthetic/marker_demo.log --match door --summary
```

```
firmware/test_data/synthetic/marker_demo.log: 3216 frames, 5 IDs, 6 markers, 4 broken lines skipped
counters (never reported): 100:2,8L
==============================================================================
summary of 3 markers: 1 3 5
  3/3  300 2.5
```

`3/3  300 2.5` = в кадре `300` бит 2.5 (байт 2, бит 5) изменился у всех трёх маркеров двери. С `--match volume` ответ —
`3/3  310 1.3`. 4 испорченные строки добавлены нарочно: инструмент пропускает строки, которые
похожи на кадры, но повреждены (нечётное число шестнадцатеричных цифр, больше 8 байтов,
4-значный ID).

## Как часто приходит кадр {#how-often-a-frame-comes}

Некоторым сигналам нужен кадр, который повторяется достаточно часто (см.
[Чек-лист переноса](porting-checklist.md)). Инструмент период не показывает. Определите его по
файлу:

1. Откройте запись в текстовом редакторе.
2. Найдите `can0 0F6#` (вместо `0F6` подставьте свой ID).
3. Вычтите время двух соседних строк. В `can_20261111_191045.log`:
   336.199989 - 335.699989 = 0,5 с.
4. Проверьте несколько пар. У кадра, который отправляется только при изменении, длинные
   неравномерные промежутки.

В Git Bash `grep "can0 0F6#" <файл> | head -5` выводит первые пять строк одного ID.

## От битов к значениям {#from-bits-to-values}

Поле становится числом с помощью **масштаба** (scale) и **смещения** (offset):

```
value = raw × scale + offset
```

Пример с эталонного автомобиля: наружная температура = `0F6` байт 7, масштаб 0,5, смещение -40,
то есть `value / 2 - 40` °C (измерено: совпадает с температурой, которую CAN-адаптер отправил
магнитоле, в 21 кадре из 21, `can_20261111_191045.log`). В кадре `0F6#884D1E2182585828` выше
байт 7 = `58` = 88, и 88 / 2 - 40 = 4 °C.

Чтобы найти масштаб, запишите значение в двух известных точках (например, температуру на приборной
панели или громкость магнитолы) и сравните.

### Запишите это в файл DBC {#write-it-into-a-dbc-file}

Файл DBC — текстовый файл со списком кадров и сигналов. Его читают многие инструменты CAN. Файл
эталонного автомобиля — `vehicles/peugeot-508-sw-2015/508.dbc`. Одна строка на сигнал:

```
BO_ 246 BODY_STATE: 8 CAR
 SG_ reverse : 63|1@0+ (1,0) [0|1] "" DEVICE
```

- `246` — ID в десятичном виде (`0F6` hex = 246).
- `63|1@0+`: начальный бит 63, длина 1 бит, `@0` = порядок байтов big-endian (его ещё называют
  Motorola; выберите его в SavvyCAN или cantools), `+` = без знака.
  С `@0` начальный бит = (байт - 1) × 8 + бит старшего бита поля: байт 8 бит 7 =
  7 × 8 + 7 = 63. Интервал сигналов, байт 3 биты 5-0, — это `21|6@0+`.
- `(1,0)` = масштаб и смещение; у наружной температуры `(0.5,-40)`.

Дайте каждому сигналу комментарий, который начинается с его статуса (`measured: ...` с записью
или `unverified: ...` с источником), как в `508.dbc`. Затем превратите сигналы в профиль
автомобиля: [Напишите профиль автомобиля](write-a-profile.md).

## SavvyCAN и другие инструменты {#savvycan-and-other-tools}

SavvyCAN — бесплатная настольная программа для анализа CAN, которая читает файлы DBC и файлы
журналов в нескольких форматах. У этого проекта **нет живой связи** с ней: в прошивке нет GVRET или
похожего протокола. Вы работаете с записанными файлами. Открывает ли ваша версия SavvyCAN формат
записей этого проекта напрямую, не проверялось; если она отвергает строки комментариев или
строки `uartA`, сначала экспортируйте строки CAN:

```
python -I firmware/tools/can_diff.py my_recording.log --export frames_only.log
```

## Ограничения инструмента {#limits-of-the-tool}

- У маркера нет своего времени: он получает время следующего кадра CAN. На спящей шине это момент
  её пробуждения.
- Сигнал, который меняется медленно (температура, топливо), может не измениться внутри окна.
- Бит, который уже двигался до маркера, скрыт (см. пример 4).
- Фильтр счётчиков ищет равномерные шаги. Счётчик, который прыгает, или контрольная сумма не
  распознаются и видны как постоянно меняющийся бит в каждом окне.
- Читаются только 11-битные ID (три шестнадцатеричные цифры).

Что остаётся неизвестным после расшифровки: что автомобиль делает со значением, изменения
которого вы не видели. Найденный сигнал измерен для записанных вами действий, и не более.
